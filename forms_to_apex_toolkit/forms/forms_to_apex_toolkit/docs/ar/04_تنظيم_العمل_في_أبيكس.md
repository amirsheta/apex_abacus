# تنظيم العمل في APEX بنفس ترتيب Forms ("Forms-Mirror")

**البيئة:** Oracle Database **12.1.0.2** + APEX **21.2**

**الفكرة:** نبني APEX بنفس أسماء Forms وترتيبها. أي مطور يعرف ملف `.fmb` يجد كل Block وحقل وTrigger وLOV وAlert في APEX **بنفس الاسم**، فيبقى التعديل لاحقاً سهلاً كما كان في Forms Builder.

> الملف التفصيلي الذي يلتزم به Claude Code هو `docs/apex_structure_standard.md` (بالإنجليزية). هذا الملف شرحه بالعربي.

---

## 1. التطبيقات
| في Forms | في APEX |
|---|---|
| نظام Forms واحد (قائمة `.mmb` رئيسية + شاشاتها) | تطبيق APEX واحد بنفس الاسم |
| عدة أنظمة | Workspace واحد، وتطبيق لكل نظام (مثلاً HR = 1000، INV = 2000) |
| المكتبات المشتركة `.pll` و`.olb` | حزم `pkg_lib_<name>` في القاعدة + تطبيق "Master" فيه الـ Theme والصلاحيات، وباقي التطبيقات تشترك فيه (Subscription) |

## 2. الصفحات: لكل شاشة نطاق من 10 أرقام
مثال: شاشة `ORDERS` يكون نطاقها من 120 إلى 129.

| رقم الصفحة | الاستخدام |
|---|---|
| 120 | الصفحة الرئيسية (الـ Canvas الرئيسي) |
| 121–125 | نوافذ Modal (الـ Stacked Canvas والنوافذ المنبثقة) |
| 126–128 | صفحات إضافية عند الحاجة |
| 129 | محجوزة |

- **Alias الصفحة = اسم الشاشة** (`ORDERS`)، فتصل لها بالرابط `f?p=1000:ORDERS`.
- **اسم الصفحة** = عنوان النافذة في Forms.
- **Page Group** = النظام الفرعي (مثل المبيعات)، ويعمل مثل المجلدات داخل App Builder.

## 3. المناطق (Regions) = الـ Blocks
- **Static ID للمنطقة = اسم الـ Block** (مثل `ORDERS` و`LINES`).
- ترتيب المناطق = ترتيب الـ Blocks في Forms.
- Block بسجل واحد ← Form. Block بعدة سجلات ← Interactive Grid. Control Block ← Static Content.
- Tab Canvas ← Tabs Container، وكل تبويب يحمل اسم الـ Tab Page.

## 4. الحقول: نحتفظ باسم الحقل كما هو في Forms
- `ORDERS.CUSTOMER_ID` ← `P120_CUSTOMER_ID`.
- عمود IG = اسم الحقل نفسه (`LINES.QTY` ← عمود `QTY`).
- إذا تكرر نفس اسم الحقل في Blocks مختلفة ← `P120_HDR_STATUS` (اختصار الـ Block).
- التسمية (Label) = الـ Prompt، والترتيب = ترتيب التنقل في Forms.

## 5. الـ Triggers: نفس الاسم في APEX وفي الحزمة
اسم المكوّن في APEX يُكتب بطريقة Forms نفسها: `BLOCK.ITEM.TRIGGER`.

| Trigger في Forms | المكوّن في APEX (الاسم) | الإجراء في `pkg_orders` |
|---|---|---|
| WHEN-NEW-FORM-INSTANCE | Process باسم `WHEN-NEW-FORM-INSTANCE` | `wnfi` |
| `ORDERS.CUSTOMER_ID` WHEN-VALIDATE-ITEM | Validation باسم `ORDERS.CUSTOMER_ID.WHEN-VALIDATE-ITEM` | `customer_id_wvi` |
| `ORDERS` WHEN-VALIDATE-RECORD | Validation باسم `ORDERS.WHEN-VALIDATE-RECORD` | `orders_wvr` |
| `ORDERS` PRE-INSERT | Process باسم `ORDERS.PRE-INSERT` | `orders_pre_ins` |
| `ORDERS` POST-QUERY | عمود في استعلام المنطقة | `orders_post_qry` |
| `ORDERS.BTN_POST` WHEN-BUTTON-PRESSED | زر `BTN_POST` + Process | `btn_post_wbp` |
| `ORDERS.ORDER_TYPE` WHEN-LIST-CHANGED | Dynamic Action بنفس الاسم | — |
| Program Unit باسم `CALC_TOTAL` | — | `calc_total` (نفس الاسم) |

- **الحزمة مرتبة مثل الشاشة:** المستوى العام للشاشة، ثم قسم لكل Block، ثم الـ Program Units.
- **فوق كل إجراء يبقى كود Forms الأصلي كتعليق،** لتقارن بسهولة.
- **حقل Comments في كل مكوّن APEX** فيه مصدره، مثلاً: `Source: ORDERS.CUSTOMER_ID.WHEN-VALIDATE-ITEM`.

> ⚠️ **قيد قاعدة 12.1.0.2:** أقصى طول لأي اسم في القاعدة **30 حرفاً**. إذا طال الاسم يُختصر، ويُكتب الاسم الكامل في التعليق وفي جدول السجل.

## 6. الكود المحوَّل يُقرأ مثل كود Forms (حزمة `pkg_forms_compat`)
| كود Forms | الكود بعد التحويل |
|---|---|
| `MESSAGE('تم الحفظ');` | `pkg_forms_compat.message('تم الحفظ');` |
| `MESSAGE('خطأ'); RAISE FORM_TRIGGER_FAILURE;` | `pkg_forms_compat.ftf('خطأ');` |
| `SHOW_ALERT('AL_STOP')` | `pkg_forms_compat.alert('AL_STOP');` |
| `:GLOBAL.company_id` | `pkg_forms_compat.get_global('COMPANY_ID')` |
| `:GLOBAL.x := v;` | `pkg_forms_compat.set_global('X', v);` |
| `USER` | `pkg_forms_compat.app_user` |
| `:SYSTEM.CURRENT_FORM` | `pkg_forms_compat.current_form` |

تحتوي الحزمة كذلك على **دالة معالجة أخطاء** تعرض رسائل الأعمال للمستخدم بدون `ORA-20000:`. اضبطها مرة واحدة في خصائص التطبيق.

أوامر الواجهة مثل `GO_BLOCK` و`SET_ITEM_PROPERTY` تتحول إلى Dynamic Actions.

## 7. المكونات المشتركة بنفس الأسماء
| في Forms | في APEX |
|---|---|
| LOV باسم `LOV_CUSTOMERS` | Shared LOV بنفس الاسم |
| Alert باسم `AL_CONFIRM_DEL` | Text Message بنفس الاسم (يحمل نص التنبيه) |
| `:GLOBAL.COMPANY_ID` | Application Item باسم `AI_COMPANY_ID` |
| القائمة `.mmb` | Navigation Menu بنفس الترتيب والعناوين |
| صلاحية `CLERK` في القائمة | Authorization Scheme باسم `ROLE_CLERK` |

## 8. شكل موحد للصفحات (مثل شريط أدوات Forms)
في أعلى كل صفحة رئيسية، أزرار ثابتة بنفس الترتيب:
**حفظ `SAVE` · جديد `CREATE` · حذف `DELETE` · استعلام `QUERY` · مسح `CLEAR` · خروج `EXIT`**

## 9. جدول السجل: "أين ذهب كل شيء؟"
السكربت `scripts/create_migration_registry.sql` ينشئ:
- **`MIG_FORM_REGISTRY`:** سطر لكل شاشة فيه رقم التطبيق ونطاق الصفحات والحزمة والحالة والمسؤول.
- **`MIG_OBJECT_MAP`:** سطر لكل عنصر Forms ومقابله في APEX وPL/SQL.
- **الـ View `MIG_V_WHERE_IS`:** للبحث بالاسم القديم.

مثال: "أين ذهب تحقق CUSTOMER_ID في شاشة ORDERS؟"
<div dir="ltr">

```sql
SELECT * FROM mig_v_where_is
 WHERE form_name = 'ORDERS' AND forms_object_name LIKE '%CUSTOMER_ID%';
```
</div>

Claude Code ينتج لكل شاشة ملف `registry/<form>_registry.sql` يعبّئ هذا الجدول تلقائياً (في الخطوة 03).

## 10. ما يجب مراعاته في قاعدة 12.1.0.2
- APEX 21.2 يدعم 12.1.0.2 (وهو الحد الأدنى). إصدارات APEX الأحدث (23.1 فما فوق) تحتاج قاعدة أحدث.
- **مسموح:** Identity Columns، و`DEFAULT seq.NEXTVAL`، و`FETCH FIRST`، و`JSON_TABLE` و`JSON_VALUE`.
- **ممنوع:** الأسماء الأطول من 30 حرفاً، و`LISTAGG ... ON OVERFLOW`، و`JSON_OBJECT` و`JSON_OBJECT_T` (البديل `APEX_JSON`)، وصيغة `t_rec(a => 1)` (من 18c).
- القاعدة 12.1.0.2 خارج الدعم الرسمي من Oracle، فيُنصح بوضع ترقيتها في خطة لاحقة.

## خطوات البدء بعد هذا التحديث
1. الـ DBA ينفذ `scripts/setup_apex_workspace.sql`، وأصبح السكربت يتحقق من إصدار القاعدة كذلك.
2. بمستخدم الـ Schema، نفّذ مرة واحدة: `scripts/create_migration_registry.sql` ثم `plsql_templates/pkg_forms_compat.sql`.
3. في APEX: Application Properties ← Error Handling Function = `pkg_forms_compat.apex_error_handler`.
4. وزّع نطاقات الصفحات على الشاشات في `MIG_FORM_REGISTRY`.
5. ابدأ بالشاشة الأولى من القالب 01. القوالب 02 و03 و04 و05 تطبق هذا التنظيم تلقائياً.

> **تنبيه:** السكربتات والحزم لم تُجرَّب على قاعدة 12.1.0.2 فعلية (لا تتوفر قاعدة Oracle هنا)، فنفّذها في DEV أولاً.
