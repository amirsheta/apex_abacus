# IMPR2130 – Analysis and APEX page spec (report parameter form)

Form `forms/IMPR/IMPR2130_fmb.xml` «تعديلات بيانات المستوردين» and its report `forms/IMPR/reports/IMPR2130.xml`
(Oracle Reports, data source `IMPR_UPDTS`). Package `IMPR2130` 001, page **2130**, generator
`scripts/gen_apex_impr2130.py`. Date 2026-11-25. Nothing has been compiled or imported.

**Template:** the form is the IMPR2110 screen, with the same blocks, items, triggers and program units (the XMLs differ only in
comments, item order and the count query). It follows the IMPR2110 conversion and its decisions
(`analysis/IMPR2110/IMPR2110_apex_page_spec.md` §2, §12). The page is built from the IMPR2120 generator with the
`P_TYPE` list item removed. This spec lists only the differences in detail.
The Forms module title «MAINTAIN IMPORTERS APPREVIATION CODES» was copied from another form and is not used.
The page title comes from the report: «تعديلات بيانات المستوردين».

## 1. What the form does

This is a parameter screen with no base table. The user can pick a port (head office, port 99, only) and zero or more
importer numbers (a comma list). Then the user presses **عرض [F5]** (`CHECK_VAL`) or **طباعة [F4]** (`PRINT_CHECK_VAL`).
Both count the **importer update records** (`IMPR_UPDTS` joined with `IMPORTERS` and the lookups of the report query)
of the port and the list. If there are none, they stop with «لا يوجد سجلات تحقق المطلوب». Otherwise they run report
IMPR2130 with `P_IMPR_NBR` (`CHECK_VAL`) or `CG$P_impr_nbr` (`PRINT_CHECK_VAL`), plus `P_CURR_PORT_CD`, `P_REPORT_NO`
and `P_MODULE_NAME`.

| Block | Kind | Items |
|---|---|---|
| `CALLING_PARAMETERS` | control, 1 record | `P_PORT_CD`, `P_PORT_NAME`, `LICE_NO`, buttons `SECT_LOV`, `P_LOV_PORT` |
| `CTR_BLK` | control, 5 records | `P_AGR_DESC`, `P_AGR_NBR` (hidden): the numbers in `LICE_NO` and their names |
| `TITLE` (OLB) | header | `SCREEN_NAME`, `USER_NAME`, `SYSTEM_DATE`, `SYSTEM_G_DATE`, `REPORT_NO`, `P_CURR_PORT_NAME` |
| `TOOLBAR` | buttons | `PRINT`, `VIEW`, `CLEAR`, `LOV`, `EXIT` |
| `ZATCA_LOGOS` (OLB) | logos | — |

Count query (6 branches, same FROM / WHERE): `IMPR_UPDTS IU, IMPORTERS L_IMP, IMPR_TYPE_ID_TYPES L_ITIDT, IMPR_TYPES L_IT1,
BUS_ID_TYPES L_BIT, SC_USERS L_USR, CITIES L_CT, COUNTRIES L_CTRY` as inner joins, `CITIES L_CT2` and
`CG_REF_CODES CG ('ALLOWED EXPORT')` as outer joins, then `L_IMP.PORT_CD = <port>` and `IU.IMPR_NBR = <importer>`.

## 2. Approach

The approach is the same as IMPR2110. The report is the ARD package `IMPR2130_ARD`, already generated by
`scripts/gen_ard_impr_reports.py` (only its caller note changed). Page 0 shows only PRINT, CLEAR and BACK
(`P2130_REPORT`). The custom event `REPORT_PRINT` runs FOS `IMPR2130.PRINT_CHECK_VAL`, which returns the ardpdf link
from `PRINT_IMPR2130_ARD`, and one line of JavaScript opens it in a new tab. `ARD_URL` and `ARD_DSNAME` come from
`SC_PORT_SETTING` (999 / 99).

| ARD parameter | RDF parameter | Value sent by the page |
|---|---|---|
| `P_PARAMETER1` | `P_CURR_PORT_CD` | `NVL(P2130_P_PORT_CD, P_CURR_PORT_CD)` |
| `P_PARAMETER2` | `P_IMPR_NBR` | importer list in `P2130_LICE_NO` (digits and commas; empty = all) |
| `P_PARAMETER3` | `START_DT` | empty: the form does not send it |
| `P_PARAMETER4` | `END_DT` | empty: the form does not send it (both empty = every update) |
| `P_PARAMETER5` | `P_MODULE_NAME` | `P2130_HERO_TITLE` |
| `P_PARAMETER6` | `P_REPORT_NO` | `P2130_REPORT_NO` |

The count in `PRINT_CHECK_VAL` uses the same FROM / WHERE as the ARD query (port, list, and no date filter). A PDF is
therefore only opened when it has rows.

## 6. LOV

**`LOV_IMPR2130_REP_IMPR`** = `LOV_APX.IMPORTERS(P_PORT_ITEM => 'P2130_P_PORT_CD', P_DEFAULT_PORT_ITEM => 'P_CURR_PORT_CD')`.
Its columns are D (number), ARBC_IMPR_NAME and BUS_ID. It is page-specific because the call names the port item
(as `LOV_IMPR2120_REP_IMPR`). No change to LOV_APX.

## 8. Processes (Before Header)

These are the same five processes as IMPR2110: `New` (Never), `P0_PAGE_PK CHECK`, `PARAMETERS`
(`GET_MODULE_ID … 'IMPR2130'`), `WHEN-NEW-FORM-INSTANCE` and `HEADER TITLE`. The default title of `HEADER TITLE` is
«تعديلات بيانات المستوردين».

There are no validations because the page never submits. `PRINT_CHECK_VAL` repeats the port and list checks (standard 13-b).

## 12. Findings and decisions

1. **The count matches the report.** The RDF query (in `IMPR2130_ARD`) has the same joins and the lexical
   `&P_IMPR_NBR`. Its `START_DT` / `END_DT` filter is off when both are empty, and the form never sends them.
2. **The report parameter name differs between the two program units.** `CHECK_VAL` sends `P_IMPR_NBR`, which the RDF
   has. `PRINT_CHECK_VAL` sends `CG$P_impr_nbr`, which the RDF does not have, so Forms printing listed every importer.
   Here both send the page's list (the IMPR2110 decision: VIEW = PRINT).
3. **Port in one Forms branch (SUGGESTION, to confirm).** When `:P_PORT_CD` is set and `LICE_NO` is empty, the Forms count
   uses `:PARAMETER.P_CURR_PORT_CD` (99 for the head office), while the report runs for `:P_PORT_CD`. The other five
   branches, and IMPR2110, use the report's port. `updates_count` uses the report's port in every branch. This looks
   like a copy error in the form: as written, a head-office user who picks a port without importers would get
   «لا يوجد سجلات» even though the report has rows.
4. The **list goes into SQL as numbers**, not as the lexical `' AND IU.IMPR_NBR in (…)'` (same as IMPR2110, finding 2).
5. Forms loops over the CTR_BLK records and stops at the first importer that has rows. Only the zero / non-zero result
   was used, so one `COUNT` with `IN (list)` gives the same result.
6. The importer LOV name is page-specific: `LOV_IMPR2130_REP_IMPR` (§6).
7. Shared-component id base **9213**: 9210 is used by IMPR1210 / IMPR2110, 9212 by IMPR2120, and 9230 would match IMPR1230's
   pattern. The generator's self-check found no id clash with any export.
