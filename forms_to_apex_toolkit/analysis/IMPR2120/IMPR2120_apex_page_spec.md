# IMPR2120 – Analysis and APEX page spec (report parameter form)

Form `forms/IMPR/IMPR2120_fmb.xml` «توقيفات المستوردين» and its report `forms/IMPR/reports/IMPR2120.xml`
(Oracle Reports, data source `CG$Q_IMPR_SUSPNS`). Package `IMPR2120` 001, page **2120**, generator
`scripts/gen_apex_impr2120.py`. Date 2026-11-25. Nothing has been compiled or imported.

**Template:** the form is IMPR2110 plus one list item, so it follows the IMPR2110 conversion and the decisions
recorded for it (`analysis/IMPR2110/IMPR2110_apex_page_spec.md` §2, §12). This spec lists only the differences in detail.
The Forms module title «MAINTAIN IMPORTERS APPREVIATION CODES» was copied from another form and is not used.
The page title comes from the report: «توقيفات المستوردين».

## 1. What the form does

This is a parameter screen with no base table. The user can pick a port (head office, port 99, only), zero or more
importer numbers (a comma list) and **حالة التوقيف** `P_TYPE`. Then the user presses **عرض [F5]** (`CHECK_VAL`) or
**طباعة [F4]** (`PRINT_CHECK_VAL`). Both count the importer **suspensions** (`IMPORTERS` ⋈ `IMPR_SUSPNS`) of the port that
match the status and the list. If there are none, they stop with «لا يوجد سجلات تحقق المطلوب». Otherwise they run report
IMPR2120 with `P_TYPE`, `CG$P_IMPR_NBR`, `P_CURR_PORT_CD`, `P_REPORT_NO` and `P_MODULE_NAME`.

| Block | Kind | Items |
|---|---|---|
| `CALLING_PARAMETERS` | control, 1 record | `P_PORT_CD`, `P_PORT_NAME`, `LICE_NO`, buttons `SECT_LOV`, `P_LOV_PORT`, **`P_TYPE`** |
| `CTR_BLK` | control, 5 records | `P_AGR_DESC`, `P_AGR_NBR` (hidden): the numbers in `LICE_NO` and their names |
| `TITLE` (OLB) | header | `SCREEN_NAME`, `USER_NAME`, `SYSTEM_DATE`, `SYSTEM_G_DATE`, `REPORT_NO`, `P_CURR_PORT_NAME` |
| `TOOLBAR` | buttons | `PRINT`, `VIEW`, `CLEAR`, `LOV`, `EXIT` |
| `ZATCA_LOGOS` (OLB) | logos | — |

**`P_TYPE`** is a List Item with `InitializeValue` 3. Its values are 2 = ساري, 1 = غير ساري and 3 = ساري وغير ساري.

* 2 (active): `C_DATE BETWEEN SUSPN_STRT_DT AND SUSPN_END_DT AND SUSPN_RLSE_DT IS NULL`.
* 1 (inactive): `C_DATE NOT BETWEEN … OR SUSPN_RLSE_DT IS NOT NULL`.

`C_DATE` is `HIJDATE.CUR_HIJ_DATE`; in the package it is `FORMS_APX.CUR_HIJ_DATE`.

## 2. Approach

The approach is the same as IMPR2110. The report is the ARD package `IMPR2120_ARD`, already generated by
`scripts/gen_ard_impr_reports.py`. Page 0 shows only PRINT, CLEAR and BACK (`P2120_REPORT`). The custom event `REPORT_PRINT`
runs FOS `IMPR2120.PRINT_CHECK_VAL`, which returns the ardpdf link from `PRINT_IMPR2120_ARD`, and one line of JavaScript
opens it in a new tab. `ARD_URL` and `ARD_DSNAME` come from `SC_PORT_SETTING` (999 / 99).

| ARD parameter | RDF parameter | Value sent by the page |
|---|---|---|
| `P_PARAMETER1` | `P_CURR_PORT_CD` | `NVL(P2120_P_PORT_CD, P_CURR_PORT_CD)` |
| `P_PARAMETER2` | `CG$P_IMPR_NBR` | importer list in `P2120_LICE_NO` (digits and commas; empty = all) |
| `P_PARAMETER3` | `P_TYPE` | `P2120_P_TYPE` (1 / 2 / 3) |
| `P_PARAMETER4` | `P_MODULE_NAME` | `P2120_HERO_TITLE` |
| `P_PARAMETER5` | `P_REPORT_NO` | `P2120_REPORT_NO` |

The count in `PRINT_CHECK_VAL` uses the same filter as the ARD query: port, status and list. A PDF is therefore only
opened when it has rows.

## 3. Page 2120 `IMPR2120`

The page uses the template *Zatca-Minimal_No_Navigation*, class `zf`, protection C and page group IMPR (IMPR1110). It has
no search page, never submits and does no DML.

`P_TYPE` is a static Select List because the values are fixed in the XML (CLAUDE.md §4d: static LOVs stay static). It is
inline, like IMPR1210's `P_TYPE` radio group, so no shared LOV is added.

The grid `CTR_BLK` works as in IMPR2110: its SQL splits `:P2120_LICE_NO` and joins `IMPORTERS` of `NVL(:P2120_P_PORT_CD, :P_CURR_PORT_CD)`.

## 6. LOV

**`LOV_IMPR2120_REP_IMPR`** = `LOV_APX.IMPORTERS(P_PORT_ITEM => 'P2120_P_PORT_CD', P_DEFAULT_PORT_ITEM => 'P_CURR_PORT_CD')`.
Its columns are D (number), ARBC_IMPR_NAME and BUS_ID.

IMPR2110's `LOV_REP_IMPR` cannot be reused because it names `P2110_P_PORT_CD`. A shared LOV that names a page item gets the
page prefix, as `LOV_IMPR1130_CITIES` did. No change to LOV_APX is needed: `IMPORTERS` with `P_DEFAULT_PORT_ITEM` is in 003.

## 8. Processes (Before Header)

These are the same five processes as IMPR2110: `New` (Never), `P0_PAGE_PK CHECK`, `PARAMETERS`
(`GET_MODULE_ID … 'IMPR2120'`), `WHEN-NEW-FORM-INSTANCE` and `HEADER TITLE`. The default title of `HEADER TITLE` is
«توقيفات المستوردين».

There are no validations because the page never submits. `PRINT_CHECK_VAL` repeats the port, list and `P_TYPE` checks (standard 13-b).

## 12. Findings and decisions

1. **The count matches the report.** The RDF query `CG$Q_IMPR_SUSPNS` (in `IMPR2120_ARD`) uses the same status
   conditions and the lexical `&CG$P_IMPR_NBR`. Unlike IMPR2110, there is no contradiction between the form and the RDF.
2. The **list goes into SQL as numbers**, not as the lexical `' AND IMP.IMPR_NBR in (…)'` (same as IMPR2110, finding 2).
3. Forms loops over the CTR_BLK records and stops at the first importer that has rows. Only the zero / non-zero result
   was used, so one `COUNT` with `IN (list)` gives the same result.
4. `P_TYPE_VALIDATION` is new (SUGGESTION). A Forms list item cannot hold other values, but a posted APEX select list can.
5. The importer LOV name is page-specific: `LOV_IMPR2120_REP_IMPR` (§6).
6. Shared-component id base **9212**. IMPR1210 and IMPR2110 both use 9210, and 9220 would match IMPR1220's pattern.
   The self-check found no id clash with any export.
