**Complexity: COMPLEX by the rubric** (size, libraries, Designer boilerplate) · **business logic: MEDIUM–COMPLEX, largely shared with IMPR1110** · **Effort ESTIMATE: 10–14 developer-days** (reusing the IMPR1110 conversion for the 121 identical units)

IMPR1130 is an **older copy of the IMPR1110 screen** on the same table `IMPORTERS`, with the same OLB frame and libraries (PU `DEV_VERSIONS`: version 8, IMPR1110 is version 15; the module name inside the XML is still `IMPR1110_PROD_CENTRL`). It has no function modes (no `CODE` parameter, no F1–F5 / SF6, no broker authorisation, no GAZT certificate, no mobile-update dialog) but it adds `NATIONAL_NBR` (رقم المنشأة) with its own Ministry of Commerce lookup, shows `EMAIL` / `MOBILE_NO` / `IMPR_TEL_NBR` as required entry items, **allows delete** with a 33-table dependency check (`CGRI$CHK_IMPORTERS`), and opens `SUPPORT_ENTRY` at form start.

**Result: COMPLEX** (4 metrics reach Complex).

**Justification.** As for IMPR1110, the rubric is driven by size and the shared Forms frame. The business work is one single-record page on `IMPORTERS` with state-driven read-only rules (181 `Make_Field_Entrable` calls), Ministry of Commerce lookups, a central create call (`CREATE_UNI_IMPR_NEBRAS`) in PRE-INSERT and an audit / journal trail. Two thirds of the code units are identical to IMPR1110 and reuse its converted members; the differences are concentrated in 11 large units (§1.3).

**Effort ESTIMATE: 10–14 developer-days** for the main page, the search page, package `IMPR1130` (new or changed members for the 46 changed and 9 new units, the delete check), the SUPPORT_ENTRY hand-over and testing. Not included: the DB packages without source and any report reached through EXECUTE_FUNCTION.
