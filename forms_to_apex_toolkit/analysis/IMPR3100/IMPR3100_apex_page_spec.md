# IMPR3100 – Analysis and APEX page spec (report parameter form)

Form `forms/IMPR/IMPR3100_fmb.xml` «تقرير إضافات وتعديلات بيانات المستوردين (مساندة فنية)» (module comment: AC1100,
"Maintain Importers Appreviation Codes" – a Designer leftover; the form is a report screen). It prints the report
`forms/IMPR/reports/IMPR3100.xml`. Package `IMPR3100` 001, page **3100**, generator `scripts/gen_apex_impr3100.py`.
Date 2026-11-26. Nothing has been compiled or imported.

**Template:** IMPR2310 (`analysis/IMPR2310/IMPR2310_apex_page_spec.md`). Both forms read the journal `JOURNAL.IMPORTERS_JN`, and their
RDFs have the same data model and layout. The differences are:
- no `SELECT1` radio group. Every item is an optional filter that is always enabled: period, letter port, letter
  department, letter number / date, user, importer;
- new items `SUP_PORT_CD` (Popup LOV on ports), `SUPP_TITLE_CD` (department of the letter), `USER_ID` (user of the journal row);
- the RDF query filters with `NVL(:param, column)` on every parameter (`SELECT DISTINCT`).

The RDF XML was not in `forms/IMPR/reports`. It was copied there from `Downloads/apex_abacus-main/forms/IMPR/REP_XML/IMPR3100.xml`
(the folder the other reports came from).

## 1. What the form does

A parameter screen with no base table. The user picks the report type (modified / added importers) and the
filters, then presses **عرض** (`ITEM304`, KEY-F4 / KEY-F5 → PU `CHECK_VAL`) or **طباعة** (`ITEM303`, KEY-PRINT → PU
`PRINT_CHECK_VAL`).

| Block | Kind | Items (navigation order) |
|---|---|---|
| `CALLING_PARAMETERS` | control, 1 record | `REPORT` (radio), `P_PORT_CD` (+ `P_LOV_PORT`), `P_PORT_NAME`, `START_DT`, `END_DT`, `SUP_PORT_CD` (+ `SUPP_PORT_CD_LOV`), `SUP_PORT_NAME`, `SUPP_TITLE_CD` (+ `P_LOV_SUPP_TITLES`), `SUPP_TITLE_NM`, `LETTER_NBR`, `LETTER_DT`, `USER_ID` (+ `BUT1`), `USR_USR_ANAME`, `IMPR_NBR1` (+ `LOV_IMPR`), `IMPR_NAME` |
| `TITLE` (OLB) | header | `SCREEN_NAME`, `USER_NAME`, `SYSTEM_DATE`, `SYSTEM_G_DATE`, `REPORT_NO`, `P_CURR_PORT_NAME` |
| `TOOLBAR` | buttons | `ITEM306` قائمة, `ITEM305` مسح, `ITEM303` طباعة, `ITEM304` عرض, `ITEM307` خروج |
| `ZATCA_LOGOS` (OLB) | logos | — |

The two print procedures are **not** the same here (spec §12 item 1):
- **`CHECK_VAL`** (VIEW). It refuses a letter date together with a period, and END_DT < START_DT. It counts with the same
  NVL filters as the RDF and sends `P_CURR_PORT_CD` (= `:P_PORT_CD`), `START_DT`, `END_DT` (`YYYY-MM-MI`), `P_SUPP_SRCE_CD`,
  `P_IMPR_NBR`, `P_SUPP_TITLE_CD`, `P_LETTER_NBR`, `P_LETTER_DT`, `P_USER_ID`, `REPORT1`, `P_MODULE_NAME`, `P_REPORT_NO`.
- **`PRINT_CHECK_VAL`** (PRINT) is the IMPR2310 code. Its count reads `LETTER_NBR` / `START_DT` / `END_DT` with the
  SELECT1-era logic, and it sends `LTR_NBR`, `LTR_DATE`, `SUPP_SRCE_CD` (`MI-MM-RRRR`), which the RDF query never reads.

## 2. Approach

1. **Report.** `IMPR3100_ARD` (`plsql/IMPR3100`) is generated by `scripts/gen_ard_impr_reports.py` (entry `IMPR3100`). It
   uses the IMPR2310 formula code (identical in the RDF), the RDF query with its binds as variables, and the IMPR2310 layout
   (header «فرع»).
2. **Toolbar.** Page 0 shows only PRINT, CLEAR and BACK. The flag item is the Forms radio group `P3100_REPORT`.
3. **Print.** The custom event `REPORT_PRINT` runs FOS `IMPR3100.PRINT_CHECK_VAL`. That member keeps the standard name but
   holds the code of PU **CHECK_VAL** (user decision 2026-11-26). It returns the ardpdf link, which one line of JavaScript
   opens.
4. **Report server settings.** `ARD_URL` and `ARD_DSNAME` come from `SC_PORT_SETTING` (SYSOBJ_ID 999, PORT_CD 99).

## 12. Findings and decisions

1. **VIEW and PRINT differed. User decision 2026-11-26: follow CHECK_VAL.** PU `PRINT_CHECK_VAL` is the IMPR2310 code: its
   count uses the letter / period logic, and its parameters (`LTR_NBR`, `LTR_DATE`, `SUPP_SRCE_CD`, dates `MI-MM-RRRR`) are
   ignored by the RDF. In Forms, طباعة therefore printed without the letter port, department, number or user filters. The
   page has one PRINT button, which runs the CHECK_VAL checks, count and parameters.
2. **Letter date. User decision 2026-11-26: apply it.** The RDF query reads `:LETTER_DT`, but Forms sent `P_LETTER_DT`, so
   the Forms report never filtered by letter date (the count did). The ARD receives it as parameter 8 `LETTER_DT` and filters.
3. **The count and the report filter differently (SUGGESTION, kept as in Forms).** The CHECK_VAL count has its port line
   commented out; the report filters `IMP.PORT_CD = P_CURR_PORT_CD`. A match in another port passes the count and then prints
   an empty report (as IMPR2310 §12 item 1).
4. **Port sent to the report**: `NVL(P_PORT_CD, P_CURR_PORT_CD)` at head office, as IMPR2310.
5. **USER_ID port (SUGGESTION).** Forms checked the user against `:P_PORT_CD`, which is empty at head office when no port is
   picked, so every user was refused. The page uses `NVL(P_PORT_CD, P_CURR_PORT_CD)` for both the check and `LOV_USER`.
   An unknown user gives `FORMS_APX.ARABIC_MESSAGE(1, 80)` (Forms `STR.DISPARBMSG(1, 80)`).
6. **SUP_PORT_NAME on open (SUGGESTION).** WHEN-NEW-RECORD-INSTANCE set only `SUP_PORT_CD` (an assignment fires no
   WHEN-VALIDATE-ITEM, so the name stayed empty). The page also fills the name.
7. **Messages for silent failures.** Forms raised FORM_TRIGGER_FAILURE without a text for an unknown letter port or
   department. The page says «رمز الجمرك غير صحيح» (IMPR2110 text) / «رمز جهة الخطاب غير موجود» (SUPPORT_ENTRY text).
8. **Importer LOV per port (SUGGESTION)**: as IMPR2310 §12 item 4. The NVL / DISTINCT filters of the RDF also skip journal
   rows whose letter columns are NULL (`col = NVL(NULL, col)` is not true for NULL); kept as in Forms and the RDF.
9. **Dates.** `TO_CHAR(…, 'RRRR-MM-MI')` comparisons are kept (Hijri day in the minute field, the project convention). The
   letter date cannot be combined with a period, and END_DT must not be before START_DT (CHECK_VAL texts).
10. **Report header.** The RDF `DECODE(JN_OPERATION …) OPERATION` column is not in the layout, and its Arabic text is lost in
    the XML (`???`), so it is left out of the ARD.
11. **Grants.** `LIB_APX_USR` needs SELECT on `JOURNAL.IMPORTERS_JN`, `SC_USERS` and `SUPP_TITLES` too.
12. **Shared-component id base 9310** (page-digit pattern). The generator's self-check found no id clash with any export.
