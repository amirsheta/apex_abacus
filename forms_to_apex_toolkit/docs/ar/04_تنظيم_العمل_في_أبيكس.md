# تنظيم العمل في APEX بنفس ترتيب Forms ("Forms-Mirror") على التطبيق المرجعي f345

**البيئة:** Oracle Database **12.1.0.2** + APEX **21.2**

**الفكرة:** نبني APEX بنفس أسماء Forms وترتيبها. أي مطور يعرف ملف `.fmb` يجد كل Block وحقل وTrigger وLOV وAlert في APEX **بنفس الاسم**، فيبقى التعديل لاحقاً سهلاً كما كان في Forms Builder.

**التطبيق المرجعي:** كل الشاشات تُبنى داخل التطبيق المأخوذ من `apex/Reference/f345.sql`، وبنفس قوالبه وأسمائه. القواعد التفصيلية (أرقام القوالب، والـ Offset، وترتيب العمليات، وشريط الأدوات) موجودة في `docs/f345_reference_standard.md`.

> الملف التفصيلي الذي يلتزم به Claude Code هو `docs/apex_structure_standard.md` (بالإنجليزية). هذا الملف شرحه بالعربي. وإذا اختلف أي ملف مع معيار f345، **فمعيار f345 هو المعتمد.**

---

## 1. التطبيقات
| في Forms | في APEX |
|---|---|
| نظام Forms واحد (قائمة `.mmb` رئيسية + شاشاتها) | تطبيق APEX واحد **مثبّت من f345**، ومعه الـ Theme (نمط ZATCA Forms، من اليمين لليسار)، وشريط الأدوات في الصفحة 0، وصفحة الدخول، والـ Plug-ins، والـ Application Items |
| عدة أنظمة | Workspace واحد، وتطبيق لكل نظام، وكلها مثبّتة من f345 |
| المكتبات المشتركة `.pll` و`.olb` | حزم `LIB_<name>` في القاعدة. شكل الـ `.olb` موجود أصلاً في f345 (القوالب والـ CSS) |

ملف الاستيراد الذي يولّده Claude Code **يضيف صفحات داخل هذا التطبيق** فقط، ولا يعيد إنشاء مكوناته المشتركة.

## 2. الصفحات: صفحة رئيسية وصفحات فرعية برقمها
- رقم الصفحة الرئيسية يأتي من جدول `MIG_FORM_REGISTRY`، مثلاً `AGR1100` ← 11100، و`IMPR1110` ← 1110.
- الصفحات الفرعية تأخذ رقم الصفحة الرئيسية ثم رقمين:

| رقم الصفحة | الاستخدام |
|---|---|
| `<page>` (مثل 11100) | الصفحة الرئيسية (الـ Canvas الرئيسي)، بقالب Zatca-Minimal_No_Navigation |
| `<page>01` (مثل 1110001) | **صفحة البحث** (Enter Query / Execute Query). زر البحث في الصفحة 0 يفتح هذا الرقم بالذات |
| `<page>02` إلى `<page>09` | نوافذ Modal أخرى (الـ Stacked Canvas، والنوافذ المنبثقة، وشاشات LOV المستدعاة) |

- **اسم الصفحة والـ Alias = اسم الشاشة** (`AGR1100`)، وصفحة البحث `AGR1100_SEARCH` / `AGR1100-SEARCH`.
- **عنوان الصفحة** = `&SYS_ANAME.`، وكلاس الـ CSS = `zf`.
- **Page Group** = النظام الفرعي، ويعمل مثل المجلدات داخل App Builder.
- **الصفحة 0** من f345، وفيها شريط الأدوات ورسالة التأكيد `ASK_DLG` والحقل `P0_PAGE_PK` (مفتاح السجل المفتوح). لا نضيف فيها منطق الشاشات.

> ⚠️ عملية `SCREEN ENTRY RESET` في f345 تمسح `P0_PAGE_PK` وحقول الصفحة عند الدخول من شاشة أخرى، ولا تحتفظ بها إلا بين `<page>` و`<page>01`. لذلك تحتاج كل نافذة `<page>02…09` عملية `G_LAST_PAGE KEEP` (After Header، فيها `:G_LAST_PAGE := <page>;`)، وإلا ضاع السجل المفتوح بعد إغلاق النافذة.

## 3. المناطق (Regions) = الـ Blocks
- **Static ID للمنطقة = اسم الـ Block** (مثل `ORDERS` و`LINES`).
- ترتيب المناطق = ترتيب الـ Blocks في Forms، والعنوان = عنوان الـ Block بالعربي.
- Block بسجل واحد ← Form بقالب Interactive Report وكلاسات `zatca-forms cg-form cg-card`.
- Block بعدة سجلات ← Interactive Grid بقالب Standard وكلاسات `cg-card cg-grid`.
- Control Block ← Static Content. Tab Canvas ← Tabs Container، وكل تبويب يحمل اسم الـ Tab Page.
- أعلى الشاشة منطقة عنوان (Hero) بكلاس `cg-hero`.
- قائمة الوظائف الجانبية (TMPLT) ← نافذة `FUNCS` فيها قائمة f345 المشتركة **Page Functions**.

## 4. الحقول: نحتفظ باسم الحقل كما هو في Forms
- `ORDERS.CUSTOMER_ID` ← `P120_CUSTOMER_ID`.
- عمود IG = اسم الحقل نفسه (`LINES.QTY` ← عمود `QTY`).
- إذا تكرر نفس اسم الحقل في Blocks مختلفة ← `P120_HDR_STATUS` (اختصار الـ Block).
- معامل الشاشة (Parameter) ← `P<page>_P_<PARAM>`، وإذا مرّرته شاشة أخرى ← Application Item باسم `P_<PARAM>`.
- التسمية (Label) = الـ Prompt، والترتيب = ترتيب التنقل في Forms. قالب التسمية Required - Above أو Optional - Above.
- كل صفحة رئيسية فيها الحقل `P<page>_MODULE_ID`.

## 5. الـ Triggers: نفس الاسم في APEX وفي الحزمة
- **اسم الحزمة = اسم الشاشة** بحروف كبيرة وبدون أي بادئة، مثل `ORDERS` و`AGR1100`.
- **لا نختصر أي اسم:** أسماء الحزم والإجراءات والدوال والمكونات تُكتب بكلمات كاملة، مثل `IMPORTERS_PRE_INSERT` و`BUS_ID_WHEN_VALIDATE_ITEM` و`CHECK_ERROR` و`<ITEM>_VALIDATION`، واسم الـ Block كاملاً. لا يُختصر الاسم إلا إذا تجاوز 30 حرفاً (نحذف `WHEN_` أولاً)، ويُكتب الاسم الكامل في التعليق. أسماء Forms الأصلية (الـ Program Units والحقول) تبقى كما هي.
- اسم المكوّن في APEX هو اسم الـ Trigger مفصولاً بمسافة، وبدون نقاط:
  - الـ Block الرئيسي: `<TRIGGER>`.
  - Block تفصيلي: `<BLOCK> <TRIGGER>`.
  - حقل: `<ITEM> <TRIGGER>`.

| Trigger في Forms | المكوّن في APEX (الاسم) | الإجراء في حزمة `ORDERS` |
|---|---|---|
| WHEN-NEW-FORM-INSTANCE | Process باسم `WHEN-NEW-FORM-INSTANCE` | `INIT_FORM` |
| `ORDERS.CUSTOMER_ID` WHEN-VALIDATE-ITEM | Validation باسم `CUSTOMER_ID VALIDATION` + Dynamic Action باسم `CUSTOMER_ID WHEN-VALIDATE-ITEM` | `CUSTOMER_ID_VALIDATION` (ترجع نص الخطأ) |
| حقل إلزامي | Validation باسم `CUSTOMER_ID REQUIRED` | `REQUIRED_VALIDATION` |
| `ORDERS` WHEN-VALIDATE-RECORD | Validation باسم `ORDERS WHEN-VALIDATE-RECORD` | `ORDERS_WHEN_VALIDATE_RECORD` |
| PRE-INSERT للـ Block الرئيسي | Process باسم `PRE-INSERT` | `PRE_INSERT` |
| PRE-INSERT للـ Block التفصيلي `LINES` | Process باسم `LINES PRE-INSERT` | `LINES_PRE_INSERT` |
| `ORDERS` POST-QUERY | عمود في استعلام المنطقة | `POST_QUERY` عند الحاجة فقط |
| `ORDERS.BTN_POST` WHEN-BUTTON-PRESSED | زر `BTN_POST` + Process باسم `BTN_POST WHEN-BUTTON-PRESSED` | `BTN_POST_WHEN_BUTTON_PRESSED` |
| `ORDERS.ORDER_TYPE` WHEN-LIST-CHANGED | Dynamic Action باسم `ORDER_TYPE WHEN-LIST-CHANGED` | — |
| أزرار شريط الأدوات (حفظ، حذف، استعلام، خروج) | أزرار الصفحة 0 | — |
| Program Unit باسم `CALC_TOTAL` | — | `CALC_TOTAL` (نفس الاسم) |

- **كل Process أو Validation سطر واحد** يستدعي الحزمة بمعاملات مسمّاة باسم الحقل بدون `I_` أو `IO_`، وحقل الصفحة `P<page>_X` يُمرَّر كـ `P_X`، مثل `AGR1100.PRE_INSERT(P_AGRMNT_NO => :P11100_AGRMNT_NO, SSO_APP_USER => :SSO_APP_USER);`.
- في كل حزمة إجراءات ثابتة: `CHECK_ERROR` (يعرض نص الخطأ) و`REQUIRED_VALIDATION` و`P0_PAGE_PK_CHECK` و`GET_MODULE_ID` و`HEADER_TITLE`.
- **الحزمة مرتبة مثل الشاشة:** المستوى العام للشاشة، ثم قسم لكل Block، ثم الـ Program Units.
- **فوق كل إجراء يبقى كود Forms الأصلي كتعليق،** لتقارن بسهولة.
- **حقل Comments في كل مكوّن APEX** فيه مصدره، مثلاً: `Source: ORDERS.CUSTOMER_ID.WHEN-VALIDATE-ITEM`.

> ⚠️ **قيد قاعدة 12.1.0.2:** أقصى طول لأي اسم في القاعدة **30 حرفاً**. إذا طال الاسم يُختصر، ويُكتب الاسم الكامل في التعليق وفي جدول السجل.

## 5أ. مكونات APEX الجاهزة أولاً، وحزمة واحدة مرتبة
التفاصيل في `docs/f345_reference_standard.md` (القسمان 9 و10).

- **أقل قدر من JavaScript:** كل سلوك في Forms يُبنى بمكونات APEX الجاهزة: Validation، وDynamic Action فيها FOS *Execute PL/SQL Code* (مع Items to Submit وItems to Return)، وأفعال APEX مثل Enable وDisable وShow وHide وSet Value وSet Focus وConfirm.
- **منع الكتابة في الحقل (Make_Field_Entrable):** بشرط Read Only على الحقل يستدعي دالة في الحزمة ترجع BOOLEAN، مثل `<ITEM>_IS_READ_ONLY`، أو بفعل Enable / Disable في الـ DA عند تغيّر قيمة.
- **ممنوع:** ملف JavaScript لكل شاشة، وعمليات AJAX Callback، وتخزين حالة الواجهة (JSON) في الحزمة. أي كود JavaScript لا يزيد عن 3 أسطر ويُذكر سببه في وثيقة التصميم.
- **حزمة واحدة لكل شاشة:** بدون حزمة وسيطة (`_APX`)، وكل إجراء يأخذ فقط الحقول التي يستخدمها كمعاملات IN / IN OUT بأسماء الحقول (بدون `I_` / `IO_`). ترتيب ثابت: الإصدار، ثم الإجراءات الثابتة، ثم مستوى الشاشة، ثم كل Block (الاستعلام، السجل، الحقول بترتيب التنقل، الحفظ، الأزرار)، ثم الـ Program Units. كل Trigger في Forms = إجراء واحد، لا يزيد عن نحو 80 سطراً.

## 6. الكود المحوَّل يُقرأ مثل كود Forms (حزمة `FORMS_APX`)
| كود Forms | الكود بعد التحويل |
|---|---|
| `MESSAGE('تم الحفظ');` | `FORMS_APX.message('تم الحفظ');` |
| `MESSAGE('خطأ'); RAISE FORM_TRIGGER_FAILURE;` | `FORMS_APX.FORM_TRIGGER_FAILURE('خطأ');` |
| `SHOW_ALERT('AL_STOP')` | `FORMS_APX.alert('AL_STOP');` |
| `:GLOBAL.company_id` | `FORMS_APX.get_global('COMPANY_ID')`، ويُحفظ في Application Item باسم `G_COMPANY_ID` |
| `:GLOBAL.x := v;` | `FORMS_APX.set_global('X', v);` |
| `USER` | `FORMS_APX.app_user` أو حقل f345 `SSO_APP_USER` |
| `:SYSTEM.CURRENT_FORM` | `FORMS_APX.current_form` |

عرض الأخطاء يتم بدالة f345 الجاهزة `APP_ERROR_HANDLER`، فلا تغيّرها.

أوامر الواجهة مثل `GO_BLOCK` و`SET_ITEM_PROPERTY` تتحول إلى Dynamic Actions.

## 7. المكونات المشتركة بنفس الأسماء
نستخدم ما هو موجود في f345، ولا ننشئ إلا الناقص.

| في Forms | في APEX |
|---|---|
| LOV باسم `LOV_CUSTOMERS` | Shared LOV بنفس الاسم |
| Alert باسم `AL_CONFIRM_DEL` | Text Message بنفس الاسم (يحمل نص التنبيه) |
| `:GLOBAL.COMPANY_ID` | Application Item باسم `G_COMPANY_ID` |
| معاملات القائمة مثل `P_CURR_PORT_CD` | حقول f345 الموجودة: `P_CURR_PORT_CD` و`P_CLASS_CD` و`P_PORT_TYPE` و`SSO_APP_USER` وغيرها |
| القائمة `.mmb` | Navigation Menu بنفس الترتيب والعناوين |
| صلاحية `CLERK` في القائمة | صلاحيات التطبيق الموجودة، ولا نُنشئ Authorization Scheme (تُوثَّق الصلاحية في وثيقة التصميم فقط) |
| صلاحيات الوظائف (TMPLT) | قائمة f345 **Page Functions** (من `SC_SYSOBJ_ROLE_PRIVS`) |

## 8. شريط الأدوات في الصفحة 0 (مثل شريط Forms)
الشريط موجود في **الصفحة 0** وهو نفسه في كل الشاشات، فلا تضع الشاشة أزراراً خاصة بها له:

**إضافة `CREATE` · تعديل `SAVE` · حذف `DELETE` · بحث `SEARCH` · مسح `CLEAR` · الوظائف `FUNCS` · رجوع `BACK`**

- يظهر `CREATE` عندما يكون `P0_PAGE_PK` فارغاً (سجل جديد)، ويظهر `SAVE` و`DELETE` عندما يكون فيه مفتاح.
- `SEARCH` يفتح صفحة البحث `<page>01`، والنقر على رقم السجل فيها يرجعه للشاشة.
- إذا كان في الصفحة حقل `P<page>_REPORT` يظهر زرا العرض والطباعة بدل `FUNCS`.

## 9. جدول السجل: "أين ذهب كل شيء؟"
السكربت `scripts/create_migration_registry.sql` ينشئ:
- **`MIG_FORM_REGISTRY`:** سطر لكل شاشة فيه رقم التطبيق والصفحة الرئيسية واسم الحزمة (= اسم الشاشة) والحالة والمسؤول.
- **`MIG_OBJECT_MAP`:** سطر لكل عنصر Forms ومقابله في APEX وPL/SQL. أزرار شريط الأدوات مسجلة على الصفحة 0.
- **الـ View `MIG_V_WHERE_IS`:** للبحث بالاسم القديم.

مثال: "أين ذهب تحقق CUSTOMER_ID في شاشة ORDERS؟"
<div dir="ltr">

```sql
SELECT * FROM mig_v_where_is
 WHERE form_name = 'ORDERS' AND forms_object_name LIKE '%CUSTOMER_ID%';
```
</div>

Claude Code ينتج لكل شاشة ملف `registry/<form>_registry.sql` يعبّئ هذا الجدول تلقائياً (في الخطوة 03).

## 10. ما يجب مراعاته في قاعدة 12.1.0.2
- APEX 21.2 يدعم 12.1.0.2 (وهو الحد الأدنى). إصدارات APEX الأحدث (23.1 فما فوق) تحتاج قاعدة أحدث.
- **مسموح:** Identity Columns، و`DEFAULT seq.NEXTVAL`، و`FETCH FIRST`، و`JSON_TABLE` و`JSON_VALUE`.
- **ممنوع:** الأسماء الأطول من 30 حرفاً، و`LISTAGG ... ON OVERFLOW`، و`JSON_OBJECT` و`JSON_OBJECT_T` (البديل `APEX_JSON`)، وصيغة `t_rec(a => 1)` (من 18c).
- القاعدة 12.1.0.2 خارج الدعم الرسمي من Oracle، فيُنصح بوضع ترقيتها في خطة لاحقة.

## خطوات البدء
1. الـ DBA ينفذ `scripts/setup_apex_workspace.sql`، والسكربت يتحقق من إصدار القاعدة كذلك.
2. ثبّت التطبيق المرجعي `apex/Reference/f345.sql` في الـ Workspace، واحسب الـ ID Offset بالاستعلام الموجود في `docs/f345_reference_standard.md`.
3. بمستخدم الـ Schema، نفّذ مرة واحدة: `scripts/create_migration_registry.sql` ثم `plsql_templates/forms_apx.sql`.
4. سجّل رقم الصفحة الرئيسية لكل شاشة في `MIG_FORM_REGISTRY`.
5. ابدأ بالشاشة الأولى من القالب 01. القوالب 02 و03 و04 و05 تطبق هذا التنظيم تلقائياً.

> **تنبيه:** السكربتات والحزم لم تُجرَّب على قاعدة 12.1.0.2 فعلية (لا تتوفر قاعدة Oracle هنا)، فنفّذها في DEV أولاً.
