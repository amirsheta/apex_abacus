# شرح قوالب الأوامر الخمسة (للقراءة والفهم فقط)

> **مهم:** هذا الملف يشرح ما يطلبه كل قالب من Claude Code. **لا تنسخه إلى Claude Code.** انسخ دائماً القالب الإنجليزي الأصلي من مجلد `prompt_templates/`، لأن Claude Code يلتزم به بدقة أكبر.
>
> **البيئة:** Oracle Database **12.1.0.2** + APEX **21.2**، مع تنظيم "Forms-Mirror" (التفاصيل في `04_تنظيم_العمل_في_أبيكس.md`).

## طريقة استخدام أي قالب
1. افتح القالب الإنجليزي.
2. استبدل الحقول بين `{{ }}` بقيمها، مثل `{{FORM_NAME}}` ← `orders`.
3. انسخ النص الموجود داخل الإطار (```text) والصقه في Claude Code.
4. راجع الملفات الناتجة، ثم اعمل commit في Git قبل الانتقال للقالب التالي.
5. ابدأ جلسة جديدة (`/clear`) لكل شاشة.

## ترتيب القوالب
<div dir="ltr">

```
01 الجرد  ←  02 استخراج المنطق  ←  03 تصميم الصفحات  ←  04 ملف الاستيراد
                     ↓
                05 الاختبارات (يمكن تنفيذه بالتوازي مع 03 و04)
```

## القالب 01 — جرد وتحليل الشاشة (`01_inventory_analysis.md`)

**متى تستخدمه:** أول خطوة لكل شاشة، بعد تحويل ملف `.fmb` إلى XML.

**الحقول المطلوب تعبئتها:**
| الحقل | المعنى | مثال |
|---|---|---|
| `{{FORM_NAME}}` | اسم الشاشة بأحرف صغيرة وبدون امتداد | `orders` |

**ماذا يفعل Claude Code:**
- يقرأ ملف XML على أجزاء ولا يحمّله دفعة واحدة، لأن الملف قد يكون كبيراً.
- يفك ترميز كود الـ Triggers داخل XML (مثل `&#10;` الذي يعني سطراً جديداً).
- يستخرج **كل شيء بدون اختصار**:

| القسم | المحتوى |
|---|---|
| A | معلومات الشاشة العامة (الاسم والعنوان والقائمة وأول Block) |
| B | الـ Blocks: الجدول وشرط WHERE والترتيب وصلاحيات الإضافة والتعديل والحذف |
| C | الحقول لكل Block: النوع والطول والإلزامية والـ LOV والقيمة الافتراضية والتنسيق |
| D | علاقات Master-Detail |
| E | **كل الـ Triggers** مع كودها الكامل والدوال المدمجة المستخدمة |
| F | قوائم LOV والـ Record Groups |
| G | الـ Canvases والنوافذ |
| H | الـ Program Units مع الكود |
| I | الاعتماديات الخارجية: المكتبات والشاشات المستدعاة والتقارير و`HOST` والجداول |
| J | التنبيهات (Alerts) ونصوصها |
| K | المعاملات (Parameters) ومتغيرات `:GLOBAL` و`:SYSTEM` |
| L | القائمة والصلاحيات |

**تصنيف التعقيد:** بسيط أو متوسط أو معقد، حسب هذا الجدول:
| المقياس | بسيط | متوسط | معقد |
|---|---|---|---|
| عدد الـ Blocks | 1–2 | 3–5 | أكثر من 5 |
| عدد الـ Triggers | أقل من 15 | 15–50 | أكثر من 50 |
| أسطر PL/SQL | أقل من 300 | 300–1500 | أكثر من 1500 |
| علاقات Master-Detail | 0–1 | 2–3 | أكثر من 3 |
| شاشات أو مكتبات مستدعاة | 0 | 1–3 | أكثر من 3 |
| ميزات خاصة (HOST وTEXT_IO وOLE والمؤقتات والتقارير) | لا يوجد | 1 | 2 فأكثر |

يأخذ التصنيف أعلى فئة وصلت إليها مقياسان أو أكثر. ويعطي Claude Code كذلك **تقديراً تقريبياً** لعدد أيام العمل.

**تقييم المخاطر:**
- **عالي:** HOST وTEXT_IO وJava Beans والمؤقتات وPOST-QUERY الثقيل ومتغيرات GLOBAL التي تتحكم في المنطق والتقارير وكود مكتبة غير موجود وSQL ديناميكي وCOMMIT داخل Trigger وON-LOCK.
- **متوسط:** SET_ITEM_PROPERTY وMaster-Detail متعدد المستويات والـ Record Groups وقت التشغيل وTriggers من نوع ON-* وKEY-* وCALL_FORM بمعاملات.
- **منخفض:** التحققات البسيطة وقوائم LOV والقيم الافتراضية.

**الناتج:** `analysis/<form>/<form>_inventory.md` في 15 قسماً، آخرها **"أسئلة مفتوحة / مصادر مفقودة"**.

**الممنوعات:** لا يكتب أي كود في هذه الخطوة، ولا يخمّن كوداً غير موجود (يكتب MISSING SOURCE بدلاً منه).

**✅ ما تراجعه أنت:** هل الأعداد صحيحة مقارنة بما تراه في Forms Builder؟ أجب على الأسئلة المفتوحة قبل الانتقال للخطوة التالية.

## القالب 02 — استخراج المنطق إلى حزمة PL/SQL (`02_logic_extraction.md`)

**متى تستخدمه:** بعد مراجعة ملف الجرد.

**الحقول المطلوب تعبئتها:**
| الحقل | المعنى |
|---|---|
| `{{FORM_NAME}}` | اسم الشاشة |
| `{{FORM_NAME_UC}}` | اسم الشاشة بحروف كبيرة، وهو اسم الحزمة (مثل `AGR1100`) |
| `{{PAGE_ID}}` | رقم الصفحة الرئيسية من `MIG_FORM_REGISTRY`، ويدخل في أسماء المعاملات `I_P<page>_<ITEM>` |
| `{{LIST_OF_EXISTING_PKG_LIB_PACKAGES_OR_NONE}}` | حزم المكتبات المشتركة التي رُحّلت سابقاً (مثل `pkg_lib_common`)، أو `NONE` |

**ماذا يفعل Claude Code (5 خطوات):**
1. **يجمع كود كل Trigger** من XML مباشرة، ولا يعتمد على الملخص.
2. **يصنّف كل Trigger** في مجموعة واحدة:
   | المجموعة | أمثلة | مكانها في APEX |
   |---|---|---|
   | التحقق | WHEN-VALIDATE-ITEM/RECORD | دالة `<ITEM>_VAL` + Validation باسم `<ITEM> VALIDATION` + DA باسم `<ITEM> WHEN-VALIDATE-ITEM` |
   | قبل وبعد الحفظ | PRE-INSERT وPOST-UPDATE وON-* | إجراء `PRE_INSERT` (أو `<BLOCK_ABBR>_PRE_INSERT` للـ Block التفصيلي) + Process باسم `PRE-INSERT` |
   | الاستعلام | PRE-QUERY وPOST-QUERY | View أو دالة داخل SQL |
   | التهيئة | WHEN-NEW-FORM-INSTANCE وWHEN-CREATE-RECORD | Process في Before Header |
   | التنقل | WHEN-NEW-*-INSTANCE وKEY-* | تعليق ← Dynamic Action |
   | الواجهة فقط | SET_ITEM_PROPERTY وMESSAGE | تعليق ← Dynamic Action |
   | الأزرار | WHEN-BUTTON-PRESSED | يُقسم: منطق الأعمال في إجراء، والواجهة في DA. أزرار شريط الأدوات تذهب إلى شريط الصفحة 0 |
3. **يحصر دوال Forms المدمجة** التي تحتاج بديلاً، في جدول يبيّن الـ Trigger والسطر والبديل.
4. **يولّد الحزمة باسم الشاشة نفسه** (مثل `AGR1100`، بدون `pkg_`) حسب معيار f345:
   - ترتيب الحزمة مثل ترتيب الشاشة: المستوى العام، ثم قسم لكل Block بنفس الترتيب، ثم الـ Program Units بنفس أسمائها.
   - أسماء الإجراءات مثل f345: `PRE_INSERT` و`POST_UPDATE` للـ Block الرئيسي، و`MEMBERS_PRE_INSERT` للتفصيلي، و`CTRY_CD_VAL` للتحقق (ترجع نص الخطأ)، و`AGRMNT_NO_WVI` عندما يحسب التحقق قيماً أخرى. وفي كل حزمة `CHK` و`REQUIRED_VAL`.
   - الإجراءات التي يستدعيها APEX تأخذ معاملات تبدأ بـ `I_` و`IO_` باسم حقل الصفحة، مثل `IO_P11100_AGRMNT_NO`. **لا يتجاوز أي اسم 30 حرفاً** بسبب قاعدة 12.1.0.2.
   - **يبقى كود Forms الأصلي كتعليق** فوق كل إجراء.
   - يستخدم `pkg_forms_compat` حتى يبقى الكود مقروءاً مثل Forms، مثلاً `pkg_forms_compat.ftf('رسالة')` بدلاً من `MESSAGE + RAISE FORM_TRIGGER_FAILURE`.
5. **يكتب تقرير الاستخراج.**

**قواعد مهمة يلتزم بها:**
- الحزمة **لا تقرأ حقول الصفحة مباشرة،** بل تستقبل القيم كمعاملات، حتى يمكن اختبارها بدون APEX.
- لا يوجد `COMMIT` أو `ROLLBACK` داخل الحزمة، لأن APEX يدير المعاملة بنفسه.
- `SHOW_ALERT` الذي يسأل "هل أنت متأكد؟" يُقسم إلى رسالة تأكيد في APEX وإجراء ينفذ بعد الموافقة.
- `:GLOBAL.X` يتحول إلى `pkg_forms_compat.get_global('X')`، ثم إلى Application Item باسم `G_X`. ومعاملات القائمة تستخدم حقول f345 الموجودة (`P_CURR_PORT_CD` و`SSO_APP_USER` وغيرها).
- التسلسلات (Sequences) في PRE-INSERT تبقى كما هي، **ولا يغيّر الجداول.**
- كل كود الواجهة يُجمع كتعليقات `-- APEX-DA:` في قسم خاص بآخر الحزمة.
- ممنوع أي صيغة غير مدعومة في 12.1.0.2، مثل `JSON_OBJECT` و`LISTAGG ON OVERFLOW` وصيغة `t_rec(a => 1)`.

**الناتج:**
- `plsql/<form>/<form>_spec.sql` (الحزمة `<FORM>`)
- `plsql/<form>/<form>_body.sql`
- `analysis/<form>/<form>_logic_extraction.md`، ويحتوي جداول التصنيف والبدائل وأكواد الأخطاء وقائمة الـ DA والمنطق المحذوف مع سببه.

**فحص ذاتي:** يبحث Claude Code في الملفات عن `GO_BLOCK` و`SHOW_ALERT` و`:GLOBAL.` وغيرها، ويجب ألا تظهر إلا داخل التعليقات. ويتأكد أنه لا يوجد `pkg_<form>` ولا `AI_`.

**✅ ما تراجعه أنت:** ترجم (compile) الحزمة في DEV وأصلح الأخطاء، وراجع قسم "المنطق المحذوف".

## القالب 03 — تصميم صفحات APEX (`03_apex_page_design.md`)

**متى تستخدمه:** بعد أن تُترجم الحزمة بدون أخطاء.

**الحقول المطلوب تعبئتها:**
| الحقل | المعنى | مثال |
|---|---|---|
| `{{FORM_NAME}}` | اسم الشاشة | `orders` |
| `{{APP_ID}}` | رقم التطبيق المثبّت من f345 | `345` |
| `{{PAGE_ID}}` | رقم الصفحة الرئيسية من جدول `MIG_FORM_REGISTRY` | `11100` (وصفحة البحث 1110001) |
| `{{SUBSYSTEM}}` | النظام الفرعي، ويُستخدم كـ Page Group | `SALES` |
| `{{AUTHORIZATION_SCHEME_NAME}}` | مخطط الصلاحية | `ROLE_CLERK` |

**ماذا يفعل Claude Code:** يطبّق **معيار f345 إلزامياً** (الصفحة الرئيسية، وصفحة البحث `<page>01`، وشريط الأدوات في الصفحة 0، والقوالب والأسماء)، ثم يصمم:

| القسم | المحتوى |
|---|---|
| 1 | **نوع كل Block في APEX:** سجل واحد ← Form، وعدة سجلات قابلة للتعديل ← Interactive Grid، وللقراءة ← Interactive Report، وMaster-Detail ← Form + IG أو IG + IG، وControl Block ← Static Content، وTab Canvas ← Tabs Container |
| 2 | الصفحات: أرقامها ونوعها (عادية أو Modal) وصلاحياتها |
| 3 | المناطق: النوع والاستعلام الكامل والمفتاح الأساسي |
| 4 | الحقول: `P120_<اسم حقل Forms>` والنوع والتسمية والإلزامية والتنسيق |
| 5 | الأزرار الخاصة بالشاشة فقط. أزرار الشريط (CREATE · SAVE · DELETE · SEARCH · CLEAR · FUNCS · BACK) في الصفحة 0 |
| 6 | قوائم LOV: أقل من 50 قيمة ← Select List، وأكثر ← Popup LOV |
| 7 | التحققات، وكلها تستدعي الحزمة: `return ORDERS.CUSTOMER_ID_VAL(I_P120_CUSTOMER_ID => :P120_CUSTOMER_ID);` |
| 8 | العمليات بترتيب f345: `PRE-INSERT` عند CREATE، و`PRE-UPDATE` عند SAVE، و`P0_PAGE_PK AFTER INSERT`، وPOST-QUERY ← عمود في الاستعلام |
| 9 | الحسابات (Computations) |
| 10 | الـ Dynamic Actions من تعليقات `APEX-DA` |
| 11 | التنبيهات: معلوماتية ← رسالة نجاح، وإيقاف ← Text Message، وسؤال نعم/لا ← Confirm |
| 12 | التنقل: CALL_FORM ← Modal Dialog برقم `<page>02…09`، وNEW_FORM ← رابط |
| 13 | المكونات المشتركة المطلوبة |
| 14 | **مصفوفة التتبع:** كل عنصر في الجرد ومقابله في APEX وحالته (محوّل أو محذوف أو TODO) |
| 15 | سكربت تعبئة جدول السجل |

**الناتج:**
- `analysis/<form>/<form>_apex_page_spec.md`
- `registry/<form>_registry.sql`، ويعبّئ `MIG_FORM_REGISTRY` و`MIG_OBJECT_MAP`.

**✅ ما تراجعه أنت:** وثيقة التصميم مع قائد الفريق أو مسؤول الأعمال. **تأكد أن مصفوفة التتبع تغطي 100% من عناصر الشاشة.**

## القالب 04 — توليد ملف استيراد APEX (`04_apex_export_generation.md`)

**متى تستخدمه:** بعد اعتماد وثيقة تصميم الصفحات. هذه الخطوة **اختيارية**، ويمكنك بدلاً منها بناء الصفحات يدوياً في App Builder حسب وثيقة التصميم.

> ⚠️ **تحذير:** ملف `wwv_flow_api` المولّد غير مدعوم رسمياً من Oracle. **استورده دائماً في DEV أولاً،** وخذ نسخة احتياطية، وراجع كل صفحة بعد الاستيراد.
>
> **التطبيق المرجعي:** الملف `apex/Reference/f345.sql` هو المرجع الإلزامي. ينسخ Claude Code منه أرقام القوالب والـ Offset والكلاسات والأسماء كما هي، والملف المولّد يضيف الصفحات داخل التطبيق المثبّت من f345.

**الحقول المطلوب تعبئتها:** `{{FORM_NAME}}` و`{{FORM_NAME_UC}}` و`{{APP_ID}}` و`{{PAGE_ID}}`.

**رموز تُستبدل قبل الاستيراد** (يكتبها Claude Code داخل الملف بدل القيم الحقيقية):
| الرمز | كيف تحصل على قيمته |
|---|---|
| `__WORKSPACE_ID__` | `select workspace_id from apex_workspaces where workspace = '<الاسم>';` |
| `__APP_ID__` | رقم التطبيق (يجب أن يكون التطبيق موجوداً) |
| `__SCHEMA_NAME__` | الـ Schema (في f345: `CUSTOMS`) |
| `__ID_OFFSET__` | الـ Offset للتطبيق المثبّت (في ملف f345: `64111868204433090374`). الاستعلام في `docs/f345_reference_standard.md`. أرقام القوالب لا تعمل إلا إذا كان صحيحاً |

**ماذا يفعل Claude Code:**
- يولّد ملف تصدير صفحات بصيغة APEX 21.2 (`wwv_flow_api` وليس `wwv_flow_imp`).
- يبدأ الملف بحذف الصفحة ثم إعادة إنشائها، فيمكن استيراده أكثر من مرة.
- كل Process وValidation فيه **سطر واحد يستدعي الحزمة،** ولا يحتوي منطق أعمال.
- أسماء المكونات بصيغة f345، مثل `PRE-INSERT` و`CTRY_CD VALIDATION` و`CTRY_CD WHEN-VALIDATE-ITEM`، مع تعليق المصدر.
- لا ينشئ أزرار شريط الأدوات، ولا يعيد إنشاء أي مكوّن موجود في f345.
- إذا لم يتأكد من اسم معامل، يحذفه ويذكره في ملف الملاحظات، ولا يخترع معاملات.

**الناتج:**
- `apex/<form>/f<appid>_<form>.sql`
- `apex/<form>/import_notes.md`: الرموز وطريقة الاستيراد وقائمة المراجعة بعد الاستيراد.

**✅ ما تراجعه أنت:** بعد الاستيراد في DEV، افتح كل صفحة في Page Designer، وأصلح تحذيرات القوالب، وشغّل Advisor، وجرّب الإضافة والتعديل والحذف.

## القالب 05 — الاختبارات (`05_test_generation.md`)

**متى تستخدمه:** بعد ترجمة الحزمة، ويمكن تنفيذه بالتوازي مع القالبين 03 و04.

**المتطلب المسبق:** تثبيت utPLSQL v3 في قاعدة الاختبار. **تأكد أن إصدار utPLSQL الذي تثبّته يدعم قاعدة 12.1.**

**الحقول المطلوب تعبئتها:**
| الحقل | المعنى |
|---|---|
| `{{FORM_NAME}}` | اسم الشاشة |
| `{{LEGACY_SCHEMA}}` | الـ Schema الذي تعمل عليه شاشات Forms |
| `{{NEW_SCHEMA}}` | الـ Schema الخاص بتطبيق APEX |
| `{{DB_LINK_OR_NONE}}` | DB Link إذا كانت البيانات في قاعدتين مختلفتين، أو `NONE` |

**ماذا يولّد Claude Code (3 ملفات):**

**1) اختبارات الوحدة `test_<form>.sql` (حزمة utPLSQL باسم `TEST_<FORM>`):**
- لكل إجراء: اختبار للحالة الطبيعية، واختبار لكل رسالة خطأ، واختبارات للحدود (قيم فارغة وأطوال قصوى وأرقام سالبة وتواريخ).
- كل اختبار يتراجع تلقائياً (`rollback(auto)`)، فلا يغيّر البيانات الحقيقية.
- اسم كل اختبار يذكر الـ Trigger الأصلي في Forms.
- التشغيل: `exec ut.run('test_<form>');`

**2) قائمة اختبار القبول `uat_checklist_<form>.md` (لمستخدمي الأعمال، بلغة غير تقنية):**
- جدول فيه: الخطوات، وسلوك Forms القديم، والسلوك المتوقع في APEX، والنتيجة (نجح أو فشل).
- يغطي: فتح الشاشة، والبحث، والإضافة والتعديل والحذف، وكل رسالة تحقق (القديمة والجديدة)، وكل LOV وزر وتنبيه، والتنقل، والصلاحيات.
- يوضح **فروق لوحة المفاتيح**، مثل F7/F8 في Forms مقابل زر البحث `SEARCH`، وCtrl+S مقابل `CREATE` أو `SAVE` في شريط الصفحة 0.
- قسم للفروق المقصودة، وقسم للتوقيع: مقبول، أو مقبول مع ملاحظات، أو مرفوض.

**3) سكربت مقارنة البيانات `data_compare_<form>.sql`:**
- لكل جدول: عدد الصفوف في النظامين، و`MINUS` في الاتجاهين، ومجاميع حسب الحالة والتاريخ، وبصمة (Hash) لكل صف.
- يكتب النتائج في جدول `migration_compare_results`، ثم ملخصاً بعدد الفحوص الناجحة والفاشلة.
- لا يحتوي أي كلمات مرور.

**✅ ما تراجعه أنت:** نجاح كل الاختبارات، وكل المقارنات PASS، وتوقيع مسؤول الأعمال على قائمة UAT.
