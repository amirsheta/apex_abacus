# IMPR2220 – Analysis and APEX page spec (report parameter form)

Form `forms/IMPR/IMPR2220_fmb.xml` «تفويضات الشركات الوسيطة حسب الشركة» and its report `forms/IMPR/reports/IMPR2220.xml`
(Oracle Reports, data source `AGNTS`). Package `IMPR2220` 001, page **2220**, generator
`scripts/gen_apex_impr2220.py`. Date 2026-11-26. Nothing has been compiled or imported.

**Template:** the form is the IMPR2210 screen. A diff of the two XMLs shows only removed header comments, layout
positions, the order of two module parameters, and **one code change**: both program units send the report parameter
`IMPR_NBR` as `:parameter.TRAN_SELECT` (the lexical ` AND IMP.IMPR_NBR in (<LICE_NO>)` / ` AND IMP.IMPR_NBR IS NOT NULL`)
instead of `:LICE_NO` (see §12). The page is built from the IMPR2210 generator (`scripts/gen_apex_impr2220.py`) and follows
the IMPR2110 / IMPR2130 / IMPR2210 decisions (`analysis/IMPR2210/IMPR2210_apex_page_spec.md`).
The Forms module title «MAINTAIN IMPORTERS APPREVIATION CODES» and the module comment (AC1100, IMPR_SHORTS) were copied
from another form and are not used. The page title comes from the report: «تفويضات الشركات الوسيطة حسب الشركة».

## 1. What the form does

This is a parameter screen with no base table. The user can pick a port (head office, port 99, only) and zero or more
**brokerage company** numbers. The screen label is «رقـم الـشـركة الوسيطة», and the numbers are entered as a comma
list in `LICE_NO`. Then the user presses **عرض [F5]** (`CHECK_VAL`) or **طباعة [F4]** (`PRINT_CHECK_VAL`).
Both count the **authorizations** (`AGNTS`) whose agent company `AGNTS.IMPR_NBR_AGENT_ID` (= `IMP.IMPR_NBR`) is in the
list, for the port. If there are none, they stop with «لا يوجد سجلات تحقق المطلوب». Otherwise they run report IMPR2220
with `IMPR_NBR` = `:parameter.TRAN_SELECT`, `P_CURR_PORT_CD`, `P_REPORT_NO` and `P_MODULE_NAME`. Both program units send the same
parameters.

| Block | Kind | Items |
|---|---|---|
| `CALLING_PARAMETERS` | control, 1 record | `P_PORT_CD`, `P_PORT_NAME`, `LICE_NO`, buttons `SECT_LOV`, `P_LOV_PORT` |
| `CTR_BLK` | control, 5 records | `P_AGR_DESC`, `P_AGR_NBR` (hidden): the numbers in `LICE_NO` and their names |
| `TITLE` (OLB) | header | `SCREEN_NAME`, `USER_NAME`, `SYSTEM_DATE`, `SYSTEM_G_DATE`, `REPORT_NO`, `P_CURR_PORT_NAME` |
| `TOOLBAR` | buttons | `PRINT`, `VIEW`, `CLEAR`, `LOV`, `EXIT` |
| `ZATCA_LOGOS` (OLB) | logos | — |

Count query (6 branches, same FROM / WHERE): `IMPORTERS IMP, IMPORTERS L_IMP, AGNTS AG` with
`AG.PORT_CD = L_IMP.PORT_CD AND AG.IMPR_NBR = L_IMP.IMPR_NBR AND AG.PORT_CD = IMP.PORT_CD AND AG.IMPR_NBR_AGENT_ID = IMP.IMPR_NBR`,
then `IMP.PORT_CD = <port>` and `IMP.IMPR_NBR = <company>`. The port is `:PARAMETER.P_CURR_PORT_CD` when `:P_PORT_CD`
is empty and `:P_PORT_CD` otherwise, in every branch.

## 2. Approach

The approach is the same as IMPR2110 / IMPR2130. The report is the ARD package `IMPR2220_ARD`, already generated by
`scripts/gen_ard_impr_reports.py` (groups the rows by brokerage company); only its caller note changed. Page 0 shows only PRINT, CLEAR and BACK
(`P2220_REPORT`). The custom event `REPORT_PRINT` runs FOS `IMPR2220.PRINT_CHECK_VAL`. That returns the ardpdf link
from `PRINT_IMPR2220_ARD`, and one line of JavaScript opens the link in a new tab. `ARD_URL` and `ARD_DSNAME` come from
`SC_PORT_SETTING` (999 / 99).

| ARD parameter | RDF parameter | Value sent by the page |
|---|---|---|
| `P_PARAMETER1` | `P_CURR_PORT_CD` | `NVL(P2220_P_PORT_CD, P_CURR_PORT_CD)` |
| `P_PARAMETER2` | `IMPR_NBR` | company list in `P2220_LICE_NO` (digits and commas; empty = all) |
| `P_PARAMETER3` | `L_IMPR_NBR` | empty (the form does not send it: every importer) |
| `P_PARAMETER4` | `P_MODULE_NAME` | `P2220_HERO_TITLE` |
| `P_PARAMETER5` | `P_REPORT_NO` | `P2220_REPORT_NO` |

The count in `PRINT_CHECK_VAL` (private `agents_count`) uses the same FROM / WHERE as the ARD query (port, list).
A PDF is therefore only opened when it has rows.

## 3. Page 2220 `IMPR2220`

The page uses the template *Zatca-Minimal_No_Navigation*, class `zf`, protection C and page group IMPR (IMPR1110).
It has no search page, never submits and does no DML.

The grid `CTR_BLK` works as in IMPR2130. Its SQL splits `:P2220_LICE_NO` and joins `IMPORTERS` of
`NVL(:P2220_P_PORT_CD, :P_CURR_PORT_CD)`. That is the Forms `LICE_NO.WHEN-VALIDATE-ITEM` lookup, and a missing name
shows «هذا المستورد غير موجود». The headings are «رقم الشركة الوسيطة» / «اسم الشركة الوسيطة».

## 6. LOV

**`LOV_IMPR2220_REP_IMPR`** = `LOV_APX.IMPORTERS(P_PORT_ITEM => 'P2220_P_PORT_CD', P_DEFAULT_PORT_ITEM => 'P_CURR_PORT_CD')`.
Its columns are D (number), ARBC_IMPR_NAME and BUS_ID, the same as the LOV form REP_LOV_IMPR. It is page-specific
because the call names the port item (as `LOV_IMPR2130_REP_IMPR`). No change to LOV_APX.

## 8. Processes (Before Header)

These are the same five processes as IMPR2130: `New` (Never), `P0_PAGE_PK CHECK`, `PARAMETERS`
(`GET_MODULE_ID … 'IMPR2220'`), `WHEN-NEW-FORM-INSTANCE` and `HEADER TITLE`. The default title of `HEADER TITLE` is
«تفويضات الشركات الوسيطة حسب الشركة».

There are no validations because the page never submits. `PRINT_CHECK_VAL` repeats the port and list checks (standard 13-b).

## 12. Findings and decisions

1. **The count matches the report.** The RDF query (in `IMPR2220_ARD`) has the same three tables and joins. Its filter
   `IMP.IMPR_NBR = :IMPR_NBR` becomes `IN (list)` in the ARD, because `LICE_NO` can hold several numbers.
2. **Importer LOV without a port (SUGGESTION, to confirm).** Unlike IMPR2110 / IMPR2130, the 2220 `KEY-LISTVAL` /
   `SECT_LOV` triggers do not add `P_CURR_PORT_CD` to the parameter list of `REP_LOV_IMPR`. That LOV form filters
   `IMPORTERS.PORT_CD = :PARAMETER.P_CURR_PORT_CD`, so in Forms it falls back to its design-time default **30**. The
   name lookup (`LICE_NO.WHEN-VALIDATE-ITEM`), the count and the report all use `NVL(:P_PORT_CD, :PARAMETER.P_CURR_PORT_CD)`.
   `LOV_IMPR2220_REP_IMPR` uses that port too, because a list of port 30's companies on every port looks like a copy error.
3. **One report parameter in both program units.** `CHECK_VAL` and `PRINT_CHECK_VAL` both send `IMPR_NBR` =
   `:parameter.TRAN_SELECT`, so VIEW = PRINT as in the IMPR2110 decision.
4. **The list goes into SQL as numbers, not as a lexical** (same as IMPR2110, finding 2). This is the only real
   difference from IMPR2210: there the RDF gets `:LICE_NO`, here the lexical `TRAN_SELECT` built from it
   (` AND IMP.IMPR_NBR in (<LICE_NO>)`, or ` AND IMP.IMPR_NBR IS NOT NULL` when it is empty). `IMPR2220_ARD` (generated
   earlier) already reads parameter 2 as a number list and keeps `IMP.IMPR_NBR IS NOT NULL`, so the page sends the list
   and the report rows are the same. The new `LICE_NO_VALIDATION` closes the SQL injection the Forms lexical allowed.
4a. The RDF has a second filter `L_IMPR_NBR` (one importer). The form never sends it, so `P_PARAMETER3` is sent empty
   (every importer), as IMPR2130 does with its date parameters.
5. Forms loops over the CTR_BLK records and stops at the first company that has rows. Only the zero / non-zero result
   was used, so one `COUNT` with `IN (list)` gives the same result.
6. Unlike IMPR2130 finding 3, every Forms count branch here uses the report's port, so `agents_count` keeps the Forms
   behaviour.
7. The importer LOV name is page-specific: `LOV_IMPR2220_REP_IMPR` (§6).
8. Shared-component id base **9222**, from the page number pattern of 2120 → 9212 … 2210 → 9221. The generator's
   self-check found no id clash with f345 or any other export.
