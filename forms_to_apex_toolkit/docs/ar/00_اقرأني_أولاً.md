# دليل عربي لحزمة ترحيل Oracle Forms 12c إلى Oracle APEX 21.2 باستخدام Claude Code

> **ملاحظة مهمة:** ملفات التشغيل (`CLAUDE.md` وقوالب الأوامر والسكربتات وقوالب PL/SQL) بقيت بالإنجليزية عن قصد. Claude Code يفهمها بدقة أكبر، والمصطلحات التقنية في Oracle إنجليزية أصلاً. هذا المجلد `docs/ar/` موجود **لفهمك أنت وفريقك** فقط.

---

## ما هي هذه الحزمة؟
هي مجموعة ملفات جاهزة تضعها في مستودع Git، ثم تفتح Claude Code داخله. تعطي الحزمة Claude Code القواعد والخطوات اللازمة لتحويل كل شاشة Forms إلى صفحات APEX 21.2 بطريقة منظمة وقابلة للمراجعة.

## محتويات الحزمة وشرح كل ملف

### 1) `CLAUDE.md` — "دستور" المشروع
يقرؤه Claude Code تلقائياً عند بدء كل جلسة. يحتوي على:
- **قفل الإصدار:** APEX 21.2 فقط، ويُمنع استخدام أي ميزة من إصدار 22.1 أو أحدث.
- **قواعد الإخراج:** ملفات SQL وحزم PL/SQL وملفات تصدير APEX.
- **قواعد التسمية:** الحزمة باسم الشاشة نفسه بحروف كبيرة (مثل `AGR1100`)، وأسماء الإجراءات والدوال **بكلمات كاملة بدون اختصار** (مثل `IMPORTERS_PRE_INSERT` و`CHECK_ERROR`)، ولا تُختصر إلا إذا تجاوز الاسم 30 حرفاً، و`v_` للمتغيرات، و`G_` للمتغيرات العامة (GLOBAL).
- **التطبيق المرجعي f345:** كل الشاشات تُبنى داخل التطبيق `apex/Reference/f345.sql` وبنفس قوالبه وأسمائه وشريط أدواته (التفاصيل في `docs/f345_reference_standard.md`).
- **قواعد إلزامية:**
  - لا تغيير على الجداول بدون سكربت ترحيل وسكربت تراجع (rollback).
  - شاشة واحدة لكل جلسة.
  - حفظ كل تحليل في ملف markdown.
- **الأمان:** لا كلمات مرور داخل الملفات، واستخدام `:APP_USER` لمعرفة المستخدم.
- **بدائل دوال Forms:** مثل استبدال `GO_BLOCK` و`SHOW_ALERT` و`SET_ITEM_PROPERTY`.

### 2) مجلد `prompt_templates/` — قوالب الأوامر (5 خطوات لكل شاشة)
| الملف | الوظيفة | الناتج |
|---|---|---|
| `01_inventory_analysis.md` | **الجرد والتحليل:** يقرأ ملف XML الخاص بالشاشة ويستخرج الـ Blocks والحقول والـ Triggers وقوائم LOV والتنبيهات، ويصنف التعقيد (بسيط/متوسط/معقد) والمخاطر | `<form>_inventory.md` |
| `02_logic_extraction.md` | **استخراج المنطق:** ينقل كود الـ Triggers إلى حزمة PL/SQL في قاعدة البيانات، ويترك منطق الواجهة كتعليقات لتحويله إلى Dynamic Actions | `<form>_spec.sql` و`<form>_body.sql` (الحزمة `<FORM>`) |
| `03_apex_page_design.md` | **تصميم صفحات APEX:** يحدد نوع كل منطقة (Form أو Interactive Grid أو Master-Detail) والحقول والتحققات والعمليات | `<form>_apex_page_spec.md` |
| `04_apex_export_generation.md` | **توليد ملف تصدير APEX:** ملف SQL يمكن استيراده (يجب مراجعته واستيراده في بيئة DEV أولاً) | `f<appid>_<form>.sql` |
| `05_test_generation.md` | **الاختبارات:** اختبارات utPLSQL، وقائمة UAT لمستخدمي الأعمال، وسكربت مقارنة البيانات بين النظام القديم والجديد | 3 ملفات اختبار |

**طريقة الاستخدام:** افتح القالب واستبدل الحقول `{{...}}` (مثل اسم الشاشة)، ثم انسخ النص الموجود داخل الإطار والصقه في Claude Code.

### 3) مجلد `scripts/` — سكربتات مساعدة
- **`convert_forms_to_xml.sh`:** يحوّل كل ملفات `.fmb` في مجلد معين إلى XML دفعة واحدة باستخدام أداة `frmf2xml`. يسجل نجاح أو فشل كل ملف، ويطبع ملخصاً في النهاية. يُشغَّل على سيرفر Forms.
- **`setup_apex_workspace.sql`:** ينفذه الـ DBA. ينشئ Schema باسم `FORMS_MIGRATION` ومساحة عمل (Workspace) في APEX ويمنح الصلاحيات المطلوبة. يتحقق أولاً من أن الإصدار 21.2، ويطلب كلمات المرور وقت التشغيل ولا يحفظها في الملف.

### 4) مجلد `plsql_templates/` — قوالب PL/SQL
- **`pkg_template_spec.sql` و`pkg_template_body.sql`:** هيكل جاهز لحزمة كل شاشة، فيه إجراءات قياسية:
  الحزمة مرتبة مثل الشاشة (قسم لكل Block)، وتأخذ اسم الشاشة، وأسماء الإجراءات حسب معيار f345:
  | الإجراء | يحل محل Trigger في Forms |
  |---|---|
  | `INIT_FORM` | WHEN-NEW-FORM-INSTANCE |
  | `<ITEM>_VALIDATION` (ترجع نص الخطأ) و`<ITEM>_WHEN_VALIDATE_ITEM` (تحسب القيم) | WHEN-VALIDATE-ITEM |
  | `<BLOCK>_WHEN_VALIDATE_RECORD` | WHEN-VALIDATE-RECORD |
  | `PRE_INSERT` / `PRE_UPDATE` / `PRE_DELETE` (وللـ Block التفصيلي `<BLOCK>_PRE_INSERT` …) | PRE-INSERT / PRE-UPDATE / PRE-DELETE |
  | `POST_QUERY` | POST-QUERY |
  | `CHECK_ERROR` و`REQUIRED_VALIDATION` | إجراءات ثابتة في كل حزمة |
  في القالب يُستبدل `<FORM>` باسم الشاشة و`<page>` برقم صفحتها.
- **`forms_apx.sql`:** حزمة تجعل الكود المحوَّل يشبه Forms، فيها `message` و`FORM_TRIGGER_FAILURE` و`alert` و`get_global`، إضافة إلى دالة معالجة الأخطاء.
- **`dynamic_action_patterns.sql`:** 5 أنماط جاهزة للـ Dynamic Actions:
  1. إظهار أو إخفاء حقل حسب قيمة حقل آخر.
  2. قوائم متتالية (Cascading LOV).
  3. حقل إلزامي بشرط.
  4. استدعاء إجراء PL/SQL من الصفحة.
  5. رسالة تأكيد قبل الحفظ أو الحذف.

### 5) مجلد `docs/` — التوثيق (مترجم بالعربي في هذا المجلد)
- `01_البدء_السريع.md`: خطوات البدء وسير العمل.
- `02_قائمة_التحقق.md`: قائمة مهام الترحيل وسجل المخاطر.
- `03_جدول_التحويل.md`: ما يقابل كل عنصر في Forms داخل APEX.
- **`04_تنظيم_العمل_في_أبيكس.md`:** تنظيم APEX بنفس أسماء Forms وترتيبها، وقيود قاعدة 12.1.0.2. **اقرأه قبل البدء.**
- `05_شرح_قوالب_الأوامر.md`: شرح مفصل لما يطلبه كل قالب من القوالب الخمسة، وما الذي تعبئه وتراجعه.

### 6) `scripts/create_migration_registry.sql`
ينشئ جداول السجل (`MIG_FORM_REGISTRY` و`MIG_OBJECT_MAP`) لتعرف أين ذهب كل عنصر من Forms.

---

## سير العمل باختصار
1. تحويل ملفات `.fmb` إلى XML ← باستخدام `convert_forms_to_xml.sh`.
2. تجهيز بيئة APEX ← ينفذ الـ DBA `setup_apex_workspace.sql`.
3. لكل شاشة: القالب 01 ← 02 ← 03 ← 04 ← 05، مع مراجعة بشرية وعمل commit في Git بعد كل خطوة.
4. اختبار القبول (UAT) مع المستخدمين، ثم النشر على TEST ثم PROD.

## تنبيهات مهمة
- **لا تعطِ Claude Code صلاحيات على قاعدة الإنتاج أبداً.** استخدم بيئة DEV فقط.
- **راجع كل كود يتم توليده** قبل تنفيذه.
- **ملفات تصدير APEX المولّدة (القالب 04) غير مدعومة رسمياً من Oracle،** لذلك استوردها في DEV أولاً وراجعها في Page Designer. أفضل طريقة: صدّر صفحة نموذجية من بيئتك وأعطها لـ Claude Code كمرجع.
- **ملفات SQL/PLSQL في الحزمة لم تُختبر على قاعدة Oracle فعلية،** فاختبرها في بيئة التطوير أولاً.
