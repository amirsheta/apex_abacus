# IMPR2210 – Analysis and APEX page spec (report parameter form)

Form `forms/IMPR/IMPR2210_fmb.xml` «تفويضات الشركات الوسيطة» and its report `forms/IMPR/reports/IMPR2210.xml`
(Oracle Reports, data source `AGNTS`). Package `IMPR2210` 001, page **2210**, generator
`scripts/gen_apex_impr2210.py`. Date 2026-11-26. Nothing has been compiled or imported.

**Template:** the form is the IMPR2130 screen. It has the same blocks, items, triggers and program units. The XMLs differ
only in comments, the count query, the report parameter name, and the importer LOV call (see §12).
It follows the IMPR2110 / IMPR2130 conversion and their decisions (`analysis/IMPR2110/IMPR2110_apex_page_spec.md` §2, §12,
`analysis/IMPR2130/IMPR2130_apex_page_spec.md`). The page is built from the IMPR2130 generator. This spec lists only the
differences in detail.
The Forms module title «MAINTAIN IMPORTERS APPREVIATION CODES» and the module comment (AC1100, IMPR_SHORTS) were copied
from another form and are not used. The page title comes from the report: «تفويضات الشركات الوسيطة».

## 1. What the form does

This is a parameter screen with no base table. The user can pick a port (head office, port 99, only) and zero or more
**brokerage company** numbers. The screen label is «رقـم الـشـركة الوسيطة», and the numbers are entered as a comma
list in `LICE_NO`. Then the user presses **عرض [F5]** (`CHECK_VAL`) or **طباعة [F4]** (`PRINT_CHECK_VAL`).
Both count the **authorizations** (`AGNTS`) whose agent company `AGNTS.IMPR_NBR_AGENT_ID` (= `IMP.IMPR_NBR`) is in the
list, for the port. If there are none, they stop with «لا يوجد سجلات تحقق المطلوب». Otherwise they run report IMPR2210
with `IMPR_NBR` = `:LICE_NO`, `P_CURR_PORT_CD`, `P_REPORT_NO` and `P_MODULE_NAME`. Both program units send the same
parameters.

| Block | Kind | Items |
|---|---|---|
| `CALLING_PARAMETERS` | control, 1 record | `P_PORT_CD`, `P_PORT_NAME`, `LICE_NO`, buttons `SECT_LOV`, `P_LOV_PORT` |
| `CTR_BLK` | control, 5 records | `P_AGR_DESC`, `P_AGR_NBR` (hidden): the numbers in `LICE_NO` and their names |
| `TITLE` (OLB) | header | `SCREEN_NAME`, `USER_NAME`, `SYSTEM_DATE`, `SYSTEM_G_DATE`, `REPORT_NO`, `P_CURR_PORT_NAME` |
| `TOOLBAR` | buttons | `PRINT`, `VIEW`, `CLEAR`, `LOV`, `EXIT` |
| `ZATCA_LOGOS` (OLB) | logos | — |

Count query (6 branches, same FROM / WHERE): `IMPORTERS IMP, IMPORTERS L_IMP, AGNTS AG` with
`AG.PORT_CD = L_IMP.PORT_CD AND AG.IMPR_NBR = L_IMP.IMPR_NBR AND AG.PORT_CD = IMP.PORT_CD AND AG.IMPR_NBR_AGENT_ID = IMP.IMPR_NBR`,
then `IMP.PORT_CD = <port>` and `IMP.IMPR_NBR = <company>`. The port is `:PARAMETER.P_CURR_PORT_CD` when `:P_PORT_CD`
is empty and `:P_PORT_CD` otherwise, in every branch.

## 2. Approach

The approach is the same as IMPR2110 / IMPR2130. The report is the ARD package `IMPR2210_ARD`, already generated by
`scripts/gen_ard_impr_reports.py`; only its caller note changed. Page 0 shows only PRINT, CLEAR and BACK
(`P2210_REPORT`). The custom event `REPORT_PRINT` runs FOS `IMPR2210.PRINT_CHECK_VAL`. That returns the ardpdf link
from `PRINT_IMPR2210_ARD`, and one line of JavaScript opens the link in a new tab. `ARD_URL` and `ARD_DSNAME` come from
`SC_PORT_SETTING` (999 / 99).

| ARD parameter | RDF parameter | Value sent by the page |
|---|---|---|
| `P_PARAMETER1` | `P_CURR_PORT_CD` | `NVL(P2210_P_PORT_CD, P_CURR_PORT_CD)` |
| `P_PARAMETER2` | `IMPR_NBR` | company list in `P2210_LICE_NO` (digits and commas; empty = all) |
| `P_PARAMETER3` | `P_MODULE_NAME` | `P2210_HERO_TITLE` |
| `P_PARAMETER4` | `P_REPORT_NO` | `P2210_REPORT_NO` |

The count in `PRINT_CHECK_VAL` (private `agents_count`) uses the same FROM / WHERE as the ARD query (port, list).
A PDF is therefore only opened when it has rows.

## 3. Page 2210 `IMPR2210`

The page uses the template *Zatca-Minimal_No_Navigation*, class `zf`, protection C and page group IMPR (IMPR1110).
It has no search page, never submits and does no DML.

The grid `CTR_BLK` works as in IMPR2130. Its SQL splits `:P2210_LICE_NO` and joins `IMPORTERS` of

## 6. LOV

**`LOV_IMPR2210_REP_IMPR`** = `LOV_APX.IMPORTERS(P_PORT_ITEM => 'P2210_P_PORT_CD', P_DEFAULT_PORT_ITEM => 'P_CURR_PORT_CD')`.
Its columns are D (number), ARBC_IMPR_NAME and BUS_ID, the same as the LOV form REP_LOV_IMPR. It is page-specific
because the call names the port item (as `LOV_IMPR2130_REP_IMPR`). No change to LOV_APX.

## 8. Processes (Before Header)

These are the same five processes as IMPR2130: `New` (Never), `P0_PAGE_PK CHECK`, `PARAMETERS`
(`GET_MODULE_ID … 'IMPR2210'`), `WHEN-NEW-FORM-INSTANCE` and `HEADER TITLE`. The default title of `HEADER TITLE` is
«تفويضات الشركات الوسيطة».

There are no validations because the page never submits. `PRINT_CHECK_VAL` repeats the port and list checks (standard 13-b).

## 12. Findings and decisions

1. **The count matches the report.** The RDF query (in `IMPR2210_ARD`) has the same three tables and joins. Its filter
   `IMP.IMPR_NBR = :IMPR_NBR` becomes `IN (list)` in the ARD, because `LICE_NO` can hold several numbers.
2. **Importer LOV without a port (SUGGESTION, to confirm).** Unlike IMPR2110 / IMPR2130, the 2210 `KEY-LISTVAL` /
   `SECT_LOV` triggers do not add `P_CURR_PORT_CD` to the parameter list of `REP_LOV_IMPR`. That LOV form filters
   `IMPORTERS.PORT_CD = :PARAMETER.P_CURR_PORT_CD`, so in Forms it falls back to its design-time default **30**. The
   name lookup (`LICE_NO.WHEN-VALIDATE-ITEM`), the count and the report all use `NVL(:P_PORT_CD, :PARAMETER.P_CURR_PORT_CD)`.
   `LOV_IMPR2210_REP_IMPR` uses that port too, because a list of port 30's companies on every port looks like a copy error.
3. **One report parameter in both program units.** `CHECK_VAL` and `PRINT_CHECK_VAL` both send `IMPR_NBR` (the RDF
   parameter), so VIEW = PRINT as in the IMPR2110 decision. No difference was found here (IMPR2130 had one).
4. The **list goes into SQL as numbers**, not as a lexical (same as IMPR2110, finding 2). `TRAN_SELECT` is computed in
   Forms but never sent.
5. Forms loops over the CTR_BLK records and stops at the first company that has rows. Only the zero / non-zero result
   was used, so one `COUNT` with `IN (list)` gives the same result.
6. Unlike IMPR2130 finding 3, every Forms count branch here uses the report's port, so `agents_count` keeps the Forms
   behaviour.
7. The importer LOV name is page-specific: `LOV_IMPR2210_REP_IMPR` (§6).
8. Shared-component id base **9221**, from the page number pattern of 2120 → 9212 … 2180 → 9218. The generator's
   self-check found no id clash with f345 or any other export.
