# البدء السريع — ترحيل Forms 12c إلى APEX 21.2 باستخدام Claude Code

## 1. تجهيز الحزمة
1. انسخ هذا المجلد إلى مستودع Git، واترك `CLAUDE.md` في الجذر (Claude Code يقرؤه تلقائياً).
2. ضع ملفات المصدر في `input/fmb/`، ثم نفّذ على سيرفر Forms:
<div dir="ltr">

```bash
export FORMS_PATH=/path/input/fmb
./scripts/convert_forms_to_xml.sh input/fmb ./output      # -> output/xml/<form>_fmb.xml
```
</div>

3. اطلب من الـ DBA تنفيذ `scripts/setup_apex_workspace.sql`.
4. شغّل Claude Code من جذر المستودع بالأمر: `claude`.

## 2. سير العمل لكل شاشة
| الخطوة | القالب | المدخلات | المخرجات | نقطة المراجعة |
|---|---|---|---|---|
| 1 | `01_inventory_analysis.md` | ملف XML للشاشة | `<form>_inventory.md` | الإجابة على الأسئلة المفتوحة ومراجعة الأعداد |
| 2 | `02_logic_extraction.md` | الجرد + XML | الحزمة `<FORM>` (الملفان `<form>_spec/_body.sql`) + تقرير الاستخراج | الترجمة (compile) في DEV وإصلاح الأخطاء |
| 3 | `03_apex_page_design.md` | الجرد + الاستخراج + الحزمة | `<form>_apex_page_spec.md` | موافقة المسؤول أو قائد الفريق |
| 4 | `04_apex_export_generation.md` | مواصفات الصفحة + التطبيق المرجعي `apex/Reference/f345.sql` | `f<appid>_<form>.sql` | الاستيراد في DEV والمراجعة في Page Designer |

افتح القالب، واستبدل الحقول `{{...}}`، ثم الصق محتوى الإطار في Claude Code.

## 3. إدارة السياق (الذاكرة) في Claude Code
- **شاشة واحدة لكل جلسة.** استخدم `/clear` بين الشاشات، وبين الخطوات إذا كانت الشاشة كبيرة.
- كل خطوة تكتب نتائجها في ملفات، والخطوة التالية تقرأ هذه الملفات وليس سجل المحادثة.
- استخدم `/compact` عندما تطول الجلسة، واطلب من Claude البحث (grep) داخل XML بدل قراءته كاملاً.
- للشاشات الكبيرة جداً، نفّذ الخطوة 1 لكل Block على حدة (مثلاً: "حلل الـ Blocks: ORDERS وLINES فقط") ثم ادمج النتائج.
- القواعد العامة مكانها `CLAUDE.md`، أما قرارات كل شاشة فتُكتب في `analysis/<form>/<form>_review_notes.md`.
- في نهاية كل خطوة، اطلب ملخصاً بالمهام المتبقية (TODO) وسجّله في ملاحظات المراجعة.

## 4. الشاشات التي تستدعي شاشات أخرى
- ملف الجرد يذكر استدعاءات `CALL_FORM/OPEN_FORM/NEW_FORM` ومعاملاتها. **رحّل الشاشات المستدعاة (الفرعية) أولاً،** أو احجز أرقام صفحاتها مسبقاً.
- `CALL_FORM` (نافذة تعود للشاشة الأصلية) ← صفحة Modal Dialog + Dynamic Action من نوع "Dialog Closed" لتحديث الصفحة الأصلية.
- `NEW_FORM` و`OPEN_FORM` ← رابط أو Branch إلى صفحة عادية.
- قوائم المعاملات (Parameter lists) ← حقول في الصفحة الهدف تُمرَّر في الرابط (مع Session State Protection وChecksum).
- متغيرات `:GLOBAL` المشتركة بين الشاشات ← Application Items (توثَّق مرة واحدة في `analysis/_shared/application_items.md`).

## 5. المكتبات (.pll) ومكتبات الكائنات (.olb)
- حوّل `.pll` إلى نص: `frmcmp_batch module=lib.pll module_type=LIBRARY script=YES` ← ينتج `lib.pld`.
- رحّل كل مكتبة مرة واحدة كحزمة `pkg_lib_<name>` باستخدام القالب 02 بعد تعديله لملف `.pld`، مع حذف دوال Forms الخاصة بالواجهة (تتحول إلى إرشادات JS/DA).
- رحّل المكتبات المشتركة **قبل** الشاشات التي تستخدمها.
- عناصر `.olb` (Property Classes وVisual Attributes وأشرطة الأدوات) لا تُرحَّل ككود، بل تُقابَل مرة واحدة بإعدادات Theme وTemplate Options وقالب صفحة قياسي، وتوثَّق في `analysis/_shared/olb_mapping.md`.
- يجب أن يحتوي `FORMS_PATH` على ملفات `.olb/.pll` عند تشغيل `frmf2xml`، وإلا ستنقص الخصائص الموروثة.
